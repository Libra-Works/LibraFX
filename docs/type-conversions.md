# 外部定義の型変換

型変換はグラフ上に見えるノードとして配置し、その前後を通常の接続操作でつなぎます。
登録された変換があっても、異なる型の接続を黙って許可したり、変換ノードを自動挿入したり
しません。既存の多相演算ノードで許可されたFloatのVectorへのブロードキャストだけは、
従来どおり暗黙変換です。

## ノード定義への登録

ノードJSONの任意項目 `conversions` で、変換に使う入力・出力の永続IDを指定します。
元と先の型は、そのピンの定義から取得します。成分数から推測しません。

```json
"conversions": [
  { "inputPortId": "a", "outputPortId": "value", "mode": "explicit" }
]
```

この例には `a` と `value` が実際に定義され、それぞれ異なるParameter型であることが必要です。
従来の名前なし単一出力なら `outputPortId` は省略またはnullにします。
名前付き出力を持つノードでは省略できません。Breakの各成分も別々のルールです。
同じピンの組み合わせの重複、存在しないピン、Signal、同じ型への変換、
`explicit` 以外のmodeは拒否します。1ノード最大32ルールです。

CoreのノードJSONと、選択中プロジェクトのノードディレクトリにあるJSONが対象です。
UUIDと定義の不変性、既存グラフの保持、プロジェクト切替、再読み込みは既存カタログと共通です。
Converterでは既存の `--nodes <ディレクトリ>` で同じ定義を読み込みます。
プロジェクトやGroupの保存形式、ネイティブのバイナリ形式は変更しません。

## 表示と診断

ノード一覧に明示変換の型と、名前付き出力があればそのIDを表示します。
接続時・問題一覧・コンパイル時には、未登録、候補1件、複数候補を区別します。
複数候補ではノードと出力を明示的に選びます。変換チェーンの自動探索は行いません。
非アクティブなプロジェクトのノードを、編集時の候補として提示しません。
MCPの `libera_graph_list_node_types` も `conversions` を含む定義を返します。

Matrix、Color、Quaternion、Vector4は別の型です。登録がなければ、幅が一致しても
接続できません。ColorとVector4は専用の明示変換ノードを使用します。

登録メタデータは変換アルゴリズムを実装するものではありません。
実行には既存の組み込み命令、または対応するネイティブCustom Node実装が必要です。
Custom Nodeでは型UUID・ABIと入出力型を維持したままコンパイルします。
対応するネイティブ実装がなければエンジン上で実行できません。

## 回帰確認

既存のスモークテストに `--conversion-registry` を指定します。
実行時は絶対パスの `LIBERAFX_DATA_ROOT` を隔離ディレクトリに設定してください。
定義の拒否、意味上の型の区別、名前付き出力の曖昧さ、明示ノードとUndo/Redo・保存、
実際のカタログ表示、プロジェクト切替、カスタムABIへのコンパイルを対象にしています。
