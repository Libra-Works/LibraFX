## グラフ

| 用語 | 意味 |
| --- | --- |
| VFX | 火花・煙・残像など、画面に出る視覚効果（エフェクト）です。 |
| グラフ / ノード | グラフはエフェクトの設計図です。ノードはその中の箱で、「待つ」「数値を足す」「描画を指示する」など、一つの仕事をします。 |
| ピン / ポート / 接続 | ピンはノードの接続口で、ポートとも呼びます。線で出力を入力につなぎます。公開ポートは Group の外から接続できます。 |
| パラメーター / 既定値 | パラメーターはノードが使う値です。既定値は最初から入っている値で、たとえば Delay の待ち時間を `0.55` 秒に設定できます。 |
| 型 | ピンが受け取れる値の種類です。**Float** は小数を扱える数値、**Int32** は整数、**Bool** は真か偽、**Vector3** は X・Y・Z など3つの数値の組です。**Color** には色の成分とアルファ（不透明さ）があります。 |
| Matrix / Transform | Transform は位置・向き・拡大率などを表します。Matrix（行列）にすると、こうした変換をまとめて扱えます。 |
| クォータニオン | 回転を表す4つの数値で、4つの角度ではありません。正規化して回転に使い、乗算で回転を合成し、Slerp で回転を補間します。[回転の規約](quaternion-random.md)も参照してください。 |
| シード / サンプル番号 | シードは再現可能な乱数列を選び、サンプル番号はその中の値を選びます。明示的に指定すると、計算順序が変わっても粒子ごとの結果を保てます。[乱数ノード](quaternion-random.md)も参照してください。 |
| Signal / Sequence | **Signal** は「今これを実行する」という合図で、数値は運びません。Signal の出力1つにつき接続先は1つです。複数の処理を順番に動かすには **Sequence** の出力を1本ずつつなぎます。 |

実際の接続例は[グラフ制作ガイド](authoring.md)を参照してください。

## 時間と寿命

| 用語 | 意味 |
| --- | --- |
| フレーム / FPS / 再生ヘッド | フレームはタイムライン上の番号付きの刻み、FPS は1秒あたりのフレーム数です。60 FPS なら120フレームは2秒です。再生ヘッドは現在のプレビュー位置を示します。 |
| タイムラインキー / F カーブのキー | Signal キーは指定時刻に合図を送ります。**F カーブ**のキーは「1秒時点で不透明さを `0.5` にする」など、ある時刻の値を決めます。キー間の値のつなぎ方を「補間」と呼びます。 |
| Effect Age / ローカル時間 / delta time | Effect Age はエフェクト全体が始まってからの時間です。生成されたインスタンスのローカル時間は、そのインスタンスが始まった時点から数えます。delta time は前回の更新から経過した時間です。 |
| Life Time / Destroy | **Life Time** は寿命の期限を設定します。F カーブやプレビューのループ時間とは別で、期限後も子や予約済みの処理が終わるのを待つことがあります。グラフで公開されている場合、**Destroy** Signal はインスタンスの寿命終了を知らせます。 |

<span id="groups"></span>

## Group

| 用語 | 意味 |
| --- | --- |
| ルートグラフ / 子グラフ | ルートグラフは一番外側の設計図です。子グラフは Group の内側にある設計図です。 |
| Graph Group | 複数のノードをひとまとめにして、一部のピンを外から使えるようにしたものです。独立して動くコピーは作りません。 |
| Spawnable Group / インスタンス | **Spawn** は「インスタンス」という実行中のコピーを作ります。各インスタンスは自分の時間と寿命を持ちます。たとえば先に出した火花が残っている間に、次の火花を出せます。 |
| Group アセット / リビジョン / ロック | Group アセットは再利用できる定義です。リビジョンはその保存版を指します。ロックは共有の構造を保護し、各インスタンスに設定する公開値まで固定するものではありません。 |

## エンジンとファイル

| 用語 | 意味 |
| --- | --- |
| エンジン / ホスト / ランタイム | Unity・Unreal Engine・Godot など、エフェクトを読み込んでゲームの情報を渡す側をホストと呼びます。LIBERA FX のランタイムは変換済みデータを実行し、エンジンが描画します。 |
| SDK / インテグレーション | SDK はエンジンで LIBERA FX を使うために導入するファイル一式です。インテグレーションはエンジンとランタイムをつなぎます。 |
| コンパイル / コンバーター / バイトコード | コンパイルは、編集用グラフをランタイムが読める命令に変換することです。コンバーターならエディターを開かずに変換できます。変換後の命令をバイトコードと呼びます。変換の成功は、再生や描画の成功とは別です。 |
| `.lfxproj` / `.lfxb` / 旧 `.lfxp` | `.lfxproj` は編集用のプロジェクトです。新しい `.lfxb` は単純なグラフも子エフェクトや時刻付き Signal も扱う共通パッケージです。`.lfxp` は旧パッケージの拡張子で、旧バイトコード単体の `.lfxb` とともに読み込み互換を残します。新規出力には更新後の SDK を使い、後から編集するために `.lfxproj` を残します。 |
| Game I/O / スクリプトアクション | Game I/O は、ゲームとエフェクトが名前を付けて値やイベントをやり取りする仕組みです。対応する `action.*` 出力はゲーム側のスクリプトを呼び出せますが、エディター内でスクリプトを書くノードではありません。 |
| ネイティブノード / ABI / UUID | ネイティブノードは C++ などでコンパイルされた処理をランタイムで実行します。ABI はその処理とランタイムの間のバイナリ上の取り決め、UUID は表示名を変えても同じノード定義を識別できる固定 ID です。 |

実際に再生する手順は[ゲームエンジンとの連携](engine-integration.md)を参照してください。

## アセットと描画

| 用語 | 意味 |
| --- | --- |
| アセット / バインディング | アセットは画像やモデルなどの素材です。バインディングは、エンジン上のどの素材を使うかの割り当てです。同じファイル名でも同じ素材とは限りません。 |
| テクスチャ / メッシュ / マテリアル | テクスチャは画像データ、メッシュは形状、マテリアルは描画時の表面の見え方を決める設定です。 |
| スプライト / アトラス / セル | スプライトは平面の画像です。複数の絵を1枚に詰めたテクスチャがアトラスで、その中でフレームやパーツに使う四角い領域がセルです。 |
| 描画（レンダリング） / プレビュー | 描画は、画面に見えるピクセルを作ることです。プレビューは公開や配布前の確認です。ビューアーが接続され、データが届いただけでは、エンジンが画面に描いたことにはなりません。 |
| リボン / 点の履歴 | リボンは点列を結んだ帯状の形です。点の履歴は入力位置を時間に沿って記録するため、動かした位置の軌跡を作れます。[Flexible Plane Draw](flexible-plane-draw.md)が点列を描画用の三角形に変換します。 |

## GPU パーティクル

| 用語 | 意味 |
| --- | --- |
| CPU / GPU | CPU は一般的なゲームやグラフの処理を担当します。GPU は何千もの粒子の位置更新など、似た計算を並列に行うのが得意です。 |
| カーネル / 属性 / uniform | カーネルは粒子に対して実行する計算です。属性は Velocity（速度）のように粒子ごとに保存する値です。uniform は発生位置や `deltaTime` のように、カーネルに共通して渡す値です。 |
| Spawn / Update / ビルボード | GPU の **Spawn** は粒子の初期値を決め、**Update** が時間とともに値を変えます。**RenderBillboard** は粒子をカメラに向いた平面として描きます。GPU の Spawn は粒子の初期化で、CPU の Spawnable Group が子グラフを作る処理とは別です。 |
| 型付き DSL / IR / シェーダー | 型付き DSL は GPU カーネルを書くための小さな専用言語です。IR はグラフ編集とテキスト編集が共有する中間形式です。シェーダーは GPU で実行するコードで、出力したソースだけではエフェクトは再生できません。 |

2つの編集画面は[GPU パーティクル制作](gpu-particles.md)で紹介しています。

## CPU パーティクル

| 用語 | 意味 |
| --- | --- |
| Emitter / Rate / Burst | Emitter は粒子を発生させる仕組みです。Rate は時間に沿って放出し、Burst は合図に合わせて指定数を放出します。形状によって発生する位置を決めます。 |
| Spawn / Update グラフ | Spawn は新しい粒子の初期値を決め、Update は生存中の各粒子を更新します。GPU シェーダーではなく CPU の子グラフで、Property／Signal は実行スコープを通じてやり取りします。 |
| プール / 容量 / バッチ | プールは指定した最大粒子数の保存領域です。バッチは粒子の描画処理をまとめることです。Draw ノードを大量に並べる方式とは異なります。 |
| イベントキュー | シミュレーションから所有スレッドへ通知を渡す、容量の決まった待ち行列です。粒子の計算と、エンジンやゲームの関数呼び出しを分離します。 |

対応ノード、やり取りの規則、制限は[CPU パーティクル制作](cpu-particles.md)を参照してください。

## エディターのツール

| 用語 | 意味 |
| --- | --- |
| ドック / インスペクター / アウトライナー | ドックはほかのパネルと並べて置けるパネルです。インスペクターは編集できる項目を表示し、アウトライナーは現在のグラフにあるノードを一覧表示します。 |
| 診断 / ログ / プロファイラー | 診断はピンの型違いなどの問題を指摘します。ログは処理中に出たメッセージを記録します。プロファイラーは対応プレビューから処理内容と所要時間を受け取って表示します。 |
| MCP | Model Context Protocol の略です。対応クライアントからエディターのツールを呼び出す仕組みです。ツールに接続することと、プロジェクトの情報を AI に送る許可は別です。認証情報は公開しないでください。 |

各ツールの開き方は[画面リファレンス](editor-reference.md)を参照してください。
