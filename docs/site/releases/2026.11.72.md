# 2026.11.72 Preview

Released **2026-11-22**, following 2026.11.63.
[Download this version](https://github.com/Libra-Works/LibraFX/releases/tag/v2026.11.72)
or return to [all release notes](../release-notes.md).

## What changed

- **Sprite editor animations for CPU/GPU particles.** Apply authored cells, frame
  order, per-frame durations, range, FPS and loop directly to a selected particle
  node. Layered compositions preserve visible parts and their position, rotation
  and scale keys. Settings remain editable, with undo/redo and reload support.
  Disabling the animation retains its source; regular-grid Flipbook remains separate.
- **Unity camera rendering.** Simulation prepares particle output; camera callbacks
  submit the billboards without advancing compute or particle age. Held/manual-preview
  output stays visible. Layer exclusion, Stop clear and replay have repeatable checks.
- **Prepared/shared playback.** Supported Unity, Unreal and Godot paths reuse
  prepared Core hosts and gather eligible instances for shared frame execution.
  Persistent particle component arrays, authored hierarchies, Core procedural mesh
  emitters and independent callback execution policies are included. Unsafe callbacks
  retain their required thread; this does not make all rendering allocation-free.
- **Default prepared capacity: 256** per package/options pool. Preparation workers
  remain bounded. Existing serialized capacities retain their saved values.

See the [CPU particle guide](../cpu-particles.md),
[GPU particle guide](../gpu-particles.md) and [engine setup](../engine-integration.md).

## Upgrade together

1. Keep the editable projects and back up engine bindings.
2. Install the **2026.11.72 editor, converter and matching SDKs** from the release
   above. Do not mix old native libraries with new scripts or duplicate Unity plugins.
3. Re-export effects from the editor. Sprite animations require CPU render metadata
   **4**, or GPU executable payload **4** with renderer bindings **2**. Particle-buffer
   and compute-packet layouts are unchanged; older SDKs cannot read the new metadata.
4. Verify load, Play, Stop and replay in a separate project. Prewarm reusable hosts
   during loading. Unreal's artifact is source-only: rebuild the project's Editor target.

On Unity 7 alpha, the bundled shaders need `-enable-builtin-rp-fallback`.

## Verified for this release

- Packaging CI passed MCP authoring transitions, Windows AddressSanitizer fixture
  checks, portable Core with Clang/CTest, all three desktop packages and engine SDK jobs.
- Downloaded assets passed version/revision, source-hash, install-layout and executable
  checks, plus read-only MSI ProductVersion inspection. The exported Core SDK built
  independently. Packaged Converter optimization and native pool ABI checks passed.
- **Packaged Unity SDK:** Windows / 7000.0.0a16 / D3D11 / RX 6700 XT. Built-In and an
  isolated SRP passed Play Mode framebuffer checks for CPU/GPU sequences/compositions,
  disabled animation, camera layers, held output without extra compute, Stop and replay.
- **Packaged Godot SDK:** 4.7.2 / Vulkan Mobile / RX 6700 XT. CPU/GPU packages selected
  authored cells, transformed composition parts, held at time scale zero, cleared and restarted.
- **Unreal source plugin:** local UE 5.7 / D3D11 checks passed CPU scene application/replay
  and actual GPU billboard framebuffer/import checks, including all-hidden output.

These observations do not certify Unity URP/HDRP, player/IL2CPP, cooked Unreal apps,
consoles or other engine/platform combinations. Unity/Godot native bridges in these
artifacts are for Windows x64. No Niagara performance comparison is claimed.
