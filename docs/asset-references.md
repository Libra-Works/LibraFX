# 使用中アセットと参照ビュー

「コンテンツ」ウィンドウの「使用中アセット・参照」タブを使用します。
現在のエフェクト全体を起点とする一覧と、登録範囲の双方向索引を切り替えられます。
この段階は #15 で合意した references-first です。共通固定アセットIDと
プロジェクト別エンジン対応付けは #61 で別途扱います。

## 現在のエフェクト

初期表示は「現在のエフェクトの使用中アセット」です。
現在開いているGroupだけではなく、文書全体を集計します。
通常のGroup、SpawnableGroup、参照Groupに保存された子グラフを走査し、
同じ出所内の同一参照をまとめて使用箇所数を表示します。
公開パラメーターのインスタンス値を反映し、既定値を重ねて数えません。

描画ノードのモデル／スプライト、保存されたマテリアル情報とtexture値、
GPUのTexture2D宣言（FlowMap用を含む）とレンダラーのマテリアルが対象です。
参照の宣言を数えるものであり、そのノードが実行中であることやGPUでサンプリングされた
ことを示す計測ではありません。画像付きコメントは再生資源として数えません。

一覧で資源を選ぶと、出所の文書名・Group階層・ノード名・パラメーターIDを表示します。
使用箇所を選択し「使用箇所へ移動」を押すと、該当文書とGroup階層を開き、
ノードを選択して画面内へ表示します。移動だけではグラフや履歴を編集しません。
割り当ての変更、Undo／Redo、文書切替、保存先の変更に追従します。
文書がない場合と、その表示範囲で参照が0件の場合を分けます。

## 登録範囲の索引

「登録範囲の参照索引」では、開いている文書の現在状態、選択中プロジェクトの
Groupライブラリ、明示的に登録したフォルダーを対象にします。
フォルダーを入力または選択して「登録」した後、「更新」で再帰的に読み込みます。
登録はこのウィンドウだけで有効で、閉じるかプロジェクトを切り替えると解除します。
登録フォルダーと読み込み失敗の詳細は、範囲表示の展開欄で確認できます。
ディスク変更は手動更新で取り込みます。開いている文書はディスクより現在の編集内容を優先します。

ローカルの `.lfxproj`、PNG／JPEGと、現在のGroupライブラリを索引化します。
「参照元・推定候補」は対象を使う保存箇所、
「この資源の参照先」は文書やGroupが保存している参照を表示します。
参照先を選択して、その資源の詳細へ移れます。
ライブラリのGroupと、各文書に保存したインスタンスではリビジョンが異なる場合があり、
両方を出所付きで表示します。ライブラリの出所がなくても保存された子グラフは集計します。
ライブラリの使用箇所は読み取り専用グラフで表示します。索引からGroupを編集・上書きしません。

登録済みローカル文書の使用箇所へ移動すると、通常のプロジェクト読み込みで開きます。
読み込みに失敗した文書は「文書未読・参照先は不明」と表示し、参照なしとは判断しません。
登録していない場所のファイルを、参照文字列だけを根拠に自動走査しません。

## 識別と解決状態

Groupには既存の固定UUIDを表示します。それ以外は、場所や旧参照に基づく
**索引用キー**であり、共通固定アセットIDとは表示しません。
旧Unreal参照は出所の文書／Groupごとに区別します。
別の出所で同じパス文字列が見つかっても、同一アセットとは断定せず推定候補として表示します。
接続エンジンのアセット詳細にある「登録範囲の参照を調べる」も、この候補検索です。

Unrealのパスが書かれていること、接続中であること、カタログの一部に見当たらないことは、
そのプロジェクトで解決できる／欠落している証明にはなりません。
未接続・旧参照未確認・未知の参照形式・割り当て欠落・Groupライブラリの出所不在を区別します。
未知の形式を、欠落や解決済みに置き換えません。
独自ノードでは資源らしい文字列パラメーター名から候補を拾いますが、推定であることを表示します。

## 完全性と上限

**0件でも未使用とは判定しません。** 未登録フォルダー、アクセス不能な内容、
履歴の非現在状態、別プロジェクトのライブラリ、任意の独自JSONやスクリプト、
エンジン内部依存は対象外です。保存情報がないマテリアルスロットも推測しません。
エンジン内部の依存関係を取得する機能や、Unityの資源カタログは追加していません。

登録は最大16フォルダー、ローカル資源は最大5,000件です。
文書読み込みは最大256件、1件16 MiB、合計64 MiBです。
索引の走査は最大50,000ノード・20,000参照と深さ32で、上限や読み込み失敗を明示します。
アクティブ文書、ほかの開いた文書、ライブラリ、ディスク文書の順で優先します。
隠し／システムファイルと再解析ポイントは走査しません。
これらの制限がなくても、プロジェクト全域の未使用判定には使用できません。

## 回帰確認

絶対パスの `LIBERAFX_DATA_ROOT` と隔離した出力先を指定し、
`Tests\CommentImageSmokeTests.csproj` の `--asset-references` を実行します。
合成データと実際のウィンドウ・選択コントロール・Automationボタン呼び出しで、
重複集計、Group／Spawnable／参照Group、インスタンス値、原点外ノードへの移動、
割り当てとUndo／Redo、文書切替、参照ゼロ、同名ファイルへの別場所保存、
旧参照の推定候補、ライブラリ不在、破損文書、走査キャンセルを確認します。
同じ実行で #14 の資源ワークスペースと既存の資源配送／描画作成の確認も実行します。

今回、隔離ビルドと上記の専用確認、`--asset-render`、`--gpu-editor`、
既存の既定スモークテストを確認しています。
実ユーザーの設定・Unity／Unrealプロジェクトは使用していません。
実エンジン上での資源解決、Unity／Unrealの再ビルドやコンソールSDKの検証を意味しません。
