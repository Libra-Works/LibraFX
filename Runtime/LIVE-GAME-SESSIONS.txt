Live game component sessions (#49/#50)
=====================================

This is NOT the old numerical v1/v2 session facade or an editor preview.
Unity LiberaFxLiveGameSession owns real LiberaFxSpawnableComponent GameObjects.
Unreal FLibraLiveGameSession owns real ULibraSpawnableComponents on dedicated game
actors, attached to the supplied game owner when it has a scene root. Gameplay
must opt in and route instances through this service to expose them. Existing
unregistered components and production games are not enumerated or modified.

Development transport and trust boundary
---------------------------------------
LiberaFxLiveGameEndpoint / ULibraLiveGameEndpointComponent are opt-in, local-only
isolated spool transports, deliberately SEPARATE from the preview TLS protocol.
They do not listen on a network port, scan projects, broadcast discovery, read
credentials, or introduce a password/token. Shipping UE and non-development
Unity players reject sessions. Explicitly provision a private same-user session
root in isolated artifacts; NEVER use a project, upload folder, or shared folder.

On Windows, Runtime/tools/New-LiveGameSessionRoot.ps1 creates a NEW directory
with protected current-user-only inherited ACLs using the existing OS identity.
On Unix the integrator must provision mode 0700 and private ancestors. The
runtime requires an existing absolute root; ACL provisioning is a deployment
precondition, not an assertion that arbitrary user-supplied folders are safe.
This isolation is NOT a replacement for authenticated TLS for remote clients.
Remote/multi-user transport is unsupported. No new remote endpoint is exposed.

Each connection creates a fresh unity-<nonce>/unreal-<nonce> subdirectory and an
endpoint.json descriptor containing process, engine, opaque session identity,
protocol=1 and supportedUpdate=restart-root-render-v1-v2. A local tool explicitly
selects that descriptor. Only fixed request.json/response.json are exchanged.
Commands contain compiled bytes, never a path for the engine to read. Responses
include correlated sequence, failure, selected target, and current live list.
Only one tool/one outstanding spool command is supported; requests must be
published by atomic rename. Replayed sequences and other-session IDs fail.
No transport identifier is a pointer. A session identity is NOT a credential.

Invoke-LiveGameSession.ps1 -EndpointDirectory <selected-absolute-directory>
  -Operation list
  -Operation create -CompiledPackage <absolute-converter-output.lfxp> -Label ...
  -Operation replace -Target <exact-target-from-list> -CompiledPackage <...lfxp>
  -Operation end -Target <...>
  -Operation destroy -Target <...>

The client always requests explicit restart for replacement, waits at most
15 seconds by default, and reports non-Ok as failure. A timeout does NOT prove
the operation failed; list before retrying create. It never automatically
retries mutations. The helper is optional. The editor now has a dedicated LiveGameWindow with
explicit folder selection, development-editing consent, process/session display,
live list and target selection, refresh, explicit "Apply active graph — Restart",
disconnect and cancellation. It is separate from preview/resource dispatch.
MainViewModel.LiveGame.cs exposes ShowLiveGameWindow(owner) and
CloseLiveGameWindow(); the View menu opens it and main-window shutdown closes it.
The existing converter command is:
  LiberaFxConverter convert <explicit-source.lfxproj> <isolated-output.lfxp>
    --groups <explicit-library-directory>
Use --embedded-groups only when deliberately freezing the saved group revision.
Portable resource-map exports are a separate contract; not silently loaded here.
All engine assets must already be explicitly bound in the endpoint's bindings.

Editor conversion and UI safety
------------------------------
The UI captures the FULL active document (including nested edits) on Avalonia's
UI thread when Apply is invoked, along with the explicitly selected session/
target and configured group library. It resolves latest groups and uses the
same SpawnableGroupPackage compiler and binary serializer as .lfxp conversion.
It does not save/export source files, modify history or send parameter-only
patches. Unsupported lifecycle/children/GPU/game-I/O/state migrations are
rejected before publication where possible; actual engine preflight can also
reject an update. Both failures are visible without replacing old playback.
Portable resource mapping without an engine binding context remains an explicit
compiler rejection; it is not silently discarded or sent through PreviewHost.

The client touches only fixed protocol files under the explicitly selected
endpoint directory; it rejects links, UNC paths and network drives. It performs
no search of projects or endpoint directories and opens no network transport.
One process-scoped asynchronous command lease uses editor.lock in that private
spool, while command publication uses atomic rename. It verifies descriptor
identity before every command, correlates responses and bounds protocol bytes.
No automatic mutation retries. A finite ten-second operation deadline applies
by default, with explicit cancellation. If cancellation/disconnect/timeout
occurs AFTER publication, the UI says the outcome is UNKNOWN and disables
Apply until an acknowledged list refresh reconciles game state. Cancellation
does not falsely claim rollback of a command the game may already have applied.
Disconnect/closing this window never sends destroy or stops game playback.

Worker and owner contract
-------------------------
Construct on the initialized Unity main thread / Unreal game thread. Give
workers a stable, caller-owned session reference while producers are running.
SubmitCreate/Replace copy caller-stable bytes before returning; SubmitDestroy,
SubmitNaturalEnd and TakeCompletion are also worker-safe. Submission Ok is
acceptance ONLY. Owner Process is the sole SDK creation/destruction boundary.
The endpoint pumps Process every game frame; direct users must do likewise.
The session facade itself must outlive/join its producers, as any C++ service.

Per-session enqueue order determines operations on the same instance. Bounded
request capacity includes pending, processing AND unconsumed completions.
Payload byte limits include queued and active package payloads (not all SDK/GPU
allocation). At most 16 MiB/package, <=256 instances, <=1024 request cells;
default is 32 instances, 64 requests, 64 MiB retained package payloads.
Components retain the existing host's per-template/render limits too.
IDs become usable only in a successful Create completion. Replacement keeps the
logical ID. Destroy retires its generation before slot reuse. Generation wrap
exhausts the slot. Fresh session nonces prevent cross-connection/process reuse.
SDK operations are rejected off owner thread and owner reentry returns Busy.
Workers never instantiate/destroy GameObjects, UObjects, meshes or materials.

NaturalEnd delegates to the actual component's existing lifecycle (including
children and scheduled operations); normal lifetime is never changed to forced
termination by Close. Destroy is explicit forced owner destruction. Component
evaluation/ticking is engine-owner-thread work; the session does not run a
second numerical/evaluation copy or race a job with SDK destruction.
Close stops new creates/replaces/natural-end requests but keeps accepting
Destroy, processes already accepted work, and returns NotReady until live
instances AND all completions are drained. It never force-stops on its own.

On owner teardown explicitly call ShutdownAndForceDestroy on the owner thread:
queued operations become consumable NotReady failures, new work is rejected,
and real instances are forcibly released. The endpoint does this on disable /
EndPlay. Hold the session reference long enough to consume receipts, and join
producers before releasing the facade. A component returned by Resolve is an
owner-thread diagnostic borrow, never transport data or independent ownership.

Transactional supported graph updates
-------------------------------------
Creation can use packages already supported by the actual component. Broad
package/state migration is intentionally rejected. Replacement requires BOTH
old and candidate packages to satisfy the shared portable validator:
  - manually ended root-only numerical v1/v2 program and root render bindings;
  - no templates/children, lifecycle start/destroy signals, deferred signals,
    signal/destroy routes, game I/O, GPU containers or GPU programs;
  - explicit Restart (time/defaults/lifetime/output state reset), no PreserveState.

This supports adding/removing arithmetic nodes and rewiring renderer inputs,
not merely tweaking a numerical facade. The compiler fixtures add Float + Add
and rewire the SAME existing position/ModelDraw graph from 1 to 3.
Malformed bytecode, unsupported policies/packages and missing assets fail
without changing the old component, elapsed state, renderers or handle.
Candidates use independent host work/defaults and exclusively owned transient
assets. Unity stages under an inactive owner; Unreal stages on a hidden game
actor so candidate render resources cannot flash during failed preflight.
Only successful actual component initialization commits; old component/render
owners are then retired and the candidate made visible. No broad state,
children, pending signal, host object or GPU migration is silently attempted.
Restart of components mutated independently outside the session contract is
unsupported: do not independently destroy/reconfigure diagnostic borrows.
