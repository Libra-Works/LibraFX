LIBRA RUNTIME FOR UNREAL - SOURCE INTEGRATION

Scope
  Engine-independent CPU bytecode evaluation, project-native nodes, bound values
  and parameters, explicit game-thread signals, and live editor communication.
  Spawnable playback creates bound mesh/sprite renderers and delegates GPU
  compute/billboards to the separate LibraGpuRuntime module.
  Source targets UE 5.7 and later. UHT and the Win64 Development Editor build
  succeeded using the local UE 5.7.4 SDK and MyProject28 linked installation.
  Engine task/render snapshot and independent recorder automation passed locally.
  Live MCP-to-UE scalar (20) and Vector4 ([11,22,33,44]) results, profile reception,
  and the editor profiler's live rows, native values and start/stop were verified.
  The editor WebSocket transport targets Win64, Linux (including ARM64), and
  macOS with UE's libWebSockets/OpenSSL/SSL libraries. Other targets fail closed.
  DNS uses UE's platform socket subsystem; TLS pinning remains connection-local.
  Linux/macOS builds and cross-platform live connections have not been verified.

Install (PowerShell 7)
  .\Install-LibraRuntimeForUnreal.ps1 -ProjectPath "C:\YourProject\YourProject.uproject"
  Use -Update for a previous installer-managed installation. Modified and
  conflicting unowned files are preserved; the update stops instead of replacing
  them. Project files and Config are not edited. Build the project yourself.
  Copying the source plugin folder alone is insufficient: the installer bundles
  the native Core sources and generates a separate translation unit per source.
  The standalone C ABI bridge (LbInterop.cpp) is not part of the Unreal module.

Linked development installation (no source copying)
  .\Install-LibraRuntimeForUnreal.ps1 -ProjectPath "C:\YourProject\YourProject.uproject" -Link
  Add -Update to convert an installer-managed copy. Changed/unowned source stops
  conversion. The previous directory, including build output, is retained in a
  unique .libra-plugin-backup-* directory outside Plugins. Close UE before switching.
  Windows uses a directory junction (works across drives, no symlink privilege);
  PowerShell on Linux/macOS uses a directory symbolic link. Hard links are not
  suitable for folders and do not follow editor save-by-replacement operations.
  The plugin link points directly to this repository's plugin sources. An ignored
  .libra-core-source-path file points UBT at the live native Core/include directories.
  Source edits are immediately visible; recompilation is still your responsibility.
  Core runtime and live-preview translation units are included explicitly. If a
  new Core .cpp is added, add a matching module wrapper for linked development.
  Binaries/Intermediate in the linked source plugin are ignored by Git. Projects
  sharing this link also share plugin build output; avoid simultaneous/different
  engine builds of that shared directory. Use copy installs for isolated builds.
  Run -Link again safely to check/reuse the link. Copy -Update refuses links.
  For packaging/distribution, install a fresh copy into a separate project: the
  copy installer still bundles Core and does not ship the machine-local marker.

Compiler verification
  For console portability, changes to this plugin and the embedded Core must
  compile with Clang. Use an isolated copy-installed C++ project, for example:
    Build.bat YourProjectEditor Win64 Development -Project="C:\isolated\YourProject.uproject" -Compiler=Clang -NoLink
  The -NoLink check is compilation only; it does not validate linking, execution
  or a console SDK. Perform the final Unreal build and execution check with MSVC.

Graph-authored ModelDraw Cube verification
  Generate Cube.lfxproj and Cube.lfxp with the isolated --model-draw fixture
  selector described in the Unity USAGE.txt. The same compiler-produced package
  is consumed by both adapters; it is not the handcrafted native cube program.
  Run Automation RunTests Libra.Editor.ModelDraw.CubePackage with
    -LibraModelDrawFixture=C:\isolated\cube-fixture
  using a rendering-capable Editor (not NullRHI). It checks the public
  ULibraEffectComponent, actual mesh/transform/material values and camera pixels,
  and writes Cube.Unreal.png beside the fixture.
  To also create a persistent demo in a dedicated project, explicitly pass
    -LibraModelDrawSaveDemo
    -LibraModelDrawVerificationProject=C:\isolated\YourProject.uproject
  This refuses existing sample assets/maps and writes
  /Game/LiberaFxModelDrawSample/Cube. Open that map and press Play.
  In a subsequent Editor process, run
  Automation RunTests Libra.Editor.ModelDraw.SavedScenePlay with only the
  verification-project argument to check map reload and automatic Play without
  access to the original compiler fixture directory.
  The map contains a public LibraEffectActor, embedded package, project-local
  bindings/material and PlayerStart; the engine's Cube asset is not modified.
  /Game/LiberaFxSamples/Cube.Cube is an explicit sample lookup alias bound to
  /Engine/BasicShapes/Cube.Cube here, not a confirmed portable asset identity.
  Mesh size/world units remain engine-native (Unity Cube 1 unit, UE Cube 100 cm);
  the two demonstration cameras are placed accordingly.

  For independent material selection and white/blue animation, generate the
  --model-material-animation fixture described in the Unity USAGE.txt.
  Add -LibraModelDrawMaterialAnimation to the CubePackage automation command
  and point -LibraModelDrawFixture to that new directory. Time/Cos/LerpVector4
  drive the selected material's dynamic Color pin. The check verifies material
  values and actual camera pixels at 0/1/2/4 seconds on the same mesh/MID.
  With the guarded save arguments it creates /Game/LiberaFxMaterialSample/MaterialPulse.
  Run SavedScenePlay in a fresh process with -LibraModelDrawMaterialAnimation
  and the verification-project argument to check embedded playback and color
  against the running effect clock. The original Cube demo is preserved.

Engine version compatibility
  Keep one shared plugin source for UE 5.7, 5.8 and 5.9. Use engine version
  guards only where APIs differ; do not maintain a separate source fork per SDK.
  Build DLLs separately for each engine version. Do not copy Binaries or
  Intermediate between versions or build different versions through one link.
  Use UE 5.7 for routine checks. Repeat the Clang compilation, MSVC linking and
  affected automation on every supported version at feature/release milestones,
  or earlier when a change touches a version-specific engine API.
  The current compatibility changes passed UE 5.7.4 Clang compilation, MSVC
  Editor linking and the isolated preview scene/grid regression. Full UE 5.8
  and 5.9 verification is pending; source targeting alone is not tested support.

Import and use
  ULibraEffectComponent ("Libra Effect") is the public playback entry point for
  an entire effect, including CPU logic, rendering, GPU Particle nodes and
  Spawnable groups. Do not select different components for CPU and GPU.
  Import an .lfxp package, .lfxb bytecode asset, or standalone .lfxgpu asset,
  then drag the resulting asset from Content Browser
  into the level viewport. The editor creates ALibraEffectActor with a scene
  root and one ULibraEffectComponent, assigns the dropped asset to Package and
  retains the placement transform. Standalone .lfxb and .lfxgpu assets use the
  same actor and component, with Effect or GpuEffect assigned respectively.
  Assign only one of Effect, Package, or GpuEffect. Placement does not start editor
  simulation; bAutoPlay starts playback when the game begins.
  Alternatively add Libra Effect to an existing actor and assign Package.
  SetPackage/SetEffect switch formats; assigning both properties rejects Play.
  ULibraSpawnableComponent and ULibraGpuEffectComponent remain internal helpers
  and legacy-compatible classes, but are hidden from Add Component. The effect
  component creates them as needed; package playback keeps a single tick owner.

Imported asset inspector
  Open the imported .lfxp asset in the Content Browser. Under LIBERA FX Resource
  Overrides, choose a Static Mesh, Texture2D or Material for a key listed from
  the package's delivered root and child render data (including packaged GPU
  textures). A key is exactly the delivered identity plus its kind; replacing a
  key affects every use of that key in this package. This is a local UE binding,
  not a portable mapping or an edit to the source graph. Save the uasset and
  restart playback. Existing component AssetBindings have priority; clear a
  conflicting component binding to use the package's choice. Clearing the asset
  picker restores normal lookup. A replacement must still satisfy the existing
  runtime checks (e.g. mesh slots, material parameter locators and sprite atlas
  material contract). The editor validates identity and asset class before
  recording a change. It does not infer a new material parameter mapping.
  Overrides are serialized as asset references for cooking. Reimport does not
  overwrite them or change the source project link. If export changes a key,
  refresh the list and clear the old override explicitly; it is not guessed or
  transferred to another key. The compiled payload is not rewritten by edits.
  A raw .lfxb contains bytecode only; use a resource-bearing .lfxp for these
  controls. Standalone .lfxgpu assets use the same Libra Effect placement component.

  On either .lfxp or .lfxb, set the editor-only Source Project Path to the
  original local .lfxproj, then use Open LIBERA FX. This path is independent of
  the reimport filename; the .lfxproj is never embedded or changed. On Windows,
  set LIBERAFX_EDITOR_EXECUTABLE to the full path of a current LiberaFx.exe
  before starting Unreal Editor, or register that executable as the .lfxproj
  file handler. Otherwise the action uses the platform file association (Linux
  requires xdg-open and association success is reported by the OS). If LIBERA FX
  is already running, open the source in its existing window; the standalone
  singleton does not forward new launch arguments to that instance.

  Automation source: Libra.Editor.Resources.SourceProjectPath (no launch),
  Libra.Editor.Spawnable.ReimportFixture with -LibraSpawnableFixture=<Cube.lfxp>,
  and Libra.Editor.ModelDraw.CubePackage with the compiler fixture above.

Standalone bytecode compatibility
  Convert an editor graph to .lfxb, then import that file into Unreal.
  Add a Libra Effect component to an actor and set its Effect asset.
  Play / Pause / Stop / EvaluateAtTime are available to both C++ and Blueprint.
  Read results in OnEvaluationCompleted, before the next worker evaluation starts.
  BindValue / BindParameter / BindSignal resolve UUIDs once. ReadBoundValue,
  ReadBoundParameter, SetBoundParameter and DispatchSignal use those handles.
  GetValueType reports the semantic output type, including bytecode-v10 Int32.
  Use ReadBoundInt32Value and SetBoundInt32Parameter for exact integer access.
  Float/Int32 conversions remain authored nodes; overflow reports ArithmeticOverflow.
  Rebind after changing an effect, reimporting, stopping/recreating its instance,
  or registering new native node types. Cross-instance/stale handles are rejected.
  Parameter overrides are per instance; asset bytecode is never modified.
  Signals run synchronously on the game thread after a successful evaluation.
  Their instruction budget bounds execution, not rollback of earlier side effects.
  Effect Age uses effect elapsed time and Delta Time uses the engine tick's
  delta without substituting effect substeps or applying PlayRate again.
  Initial/manual evaluations use the world's current delta. Instance Age uses
  the enclosing Spawnable clock; the component's standalone graph is the root.
  When Effect is a standalone .lfxb, the component performs raw evaluation: it does not
  use Life Time to expire playback or automatically dispatch On Start / On
  Destroy. Stop is an explicit interruption, not natural expiry.
Effect package playback
  Import an .lfxp package as a Libra Spawnable asset and assign it to the
  public Libra Effect component's Package property. It drives the engine-neutral
  SpawnableHost on the game thread using scaled TimeSeconds and the unscaled
  Unreal frame delta. Blueprint events expose Spawn/Stop/Destroy/Signal and
  named game-I/O records; methods accept game signals/properties and read root
  or active child values. RequestNaturalEnd follows the package's natural
  lifecycle; Stop is explicit and never publishes natural Destroy.
  Play(false) resumes paused package playback without replacing its scopes.
  DispatchNodeSignal addresses package node UUIDs; the existing DispatchSignal
  bound-handle API remains for standalone bytecode. ReadRootValue/ReadChildValue
  and named game I/O address package values. Package seeking, raw bound handles
  and per-node profiling flags currently reject explicitly rather than evaluating
  a separate CPU instance or silently ignoring requested behavior.
  The host owns package lifecycle, delayed work and parent/child routing.
  The component instantiates root and per-child StaticMesh components from
  render_config and updates them from that exact native instance's values.
  Spawn creates a scope; Stop releases it. Natural Destroy is a notification,
  not a second destruction. Root completion, explicit Stop, restart and
  component destruction release owned rendering/GPU resources.
  AssetBindings maps opaque identities to engine Mesh/Material/Texture objects.
  Otherwise a valid Unreal soft object path may resolve an engine asset.
  builtin:unlit-color requires an explicit runtime material binding exposing
  the authored Color parameter; no editor-only material is generated at runtime.
  Shared meshes/materials are never modified. Dynamic material instances are
  allocated once per render scope, not per frame. Exposed material identities,
  associations and texture overrides are validated before playback.
  Sprites use the engine Plane mesh and a bound builtin:sprite material (or
  explicit material override) exposing Texture and AtlasRect. Tint/Color are
  used only when exposed. Frame -1 with playing enabled follows scope-local time.
  Missing/wrong-typed assets, unsupported inputs/material parameters and invalid
  manifests reject playback with LastError instead of a partial visual fallback.
  Executable GPU manifests require current package export; legacy GPU snapshots
  alone reject with a re-export diagnostic. Each scope owns an independent
  LibraGpuEffectComponent, particle buffers, spawn cursor and seed. GPU ticking
  uses effect-scaled local elapsed time and is driven only by the Spawnable
  owner, never a second automatic component tick. GpuSpawnPerSecond controls
  emission; GPU emitter position follows the owning actor's root transform.
  Scope Stop terminates its particles; queued GPU work retains shared render
  state until the render thread has consumed it.
  At most 16 emitters/scope, 128 templates, 4096 active mesh objects and 256 MiB
  aggregate active GPU state are accepted. GPU execution requires a real SM5
  device. Root GPU auto-idle draining is unsupported: disable AutoDestroyWhenIdle
  and call RequestNaturalEnd or Stop. Per-template named game I/O is unsupported;
  use root game I/O with Spawnable Capture/Live and instance-identified outputs.

Live editor connection
  Start LIBERA FX and show its Preview panel. Use that session's access token
  and SHA-256 certificate fingerprint; neither is written into level assets.
  Add a Libra Editor Connection component to the same actor as Libra Effect.
  Target defaults to the first Libra Effect component on that actor.
  Set Host, Port (default 8766), AccessToken and CertificateFingerprint, then call
  ConnectToEditor from Blueprint or C++. Use PIE or a running standalone game.
  The client uses /preview?protocol=3 with certificate-pinned TLS, authenticates
  before subscribing, and accepts compiled LFXB programs, playback, and bounded
  compilation diagnostics. It never interprets the editable graph in the engine.
  Graph edits replace the transient program; playback-only packets reuse it.
  Rebind handles in OnPreviewProgramChanged. Continue reading completed values
  in the target component's OnEvaluationCompleted, not OnPreviewUpdated.
  Invalid programs/compilation errors leave the last accepted effect intact.
  RequestSnapshot asks for a full resynchronization. DisconnectFromEditor closes
  the transport and restores the original asset (its prior instance state is
  not restored). Reconnect explicitly after a transport failure.
  Editor restart changes the token/certificate. Pair the new values again.
  For UE on another machine/OS, set Host to the editor machine's reachable IPv4
  address and allow its Preview port through the firewall. Use the same session
  token/pin, not a different certificate or an insecure fallback.
  The token and certificate fingerprint are transient component properties.
  Do not put credentials in config files, source, logs, URLs, or cooked content.

Project-native nodes
  Add LibraRuntimeForUnreal to your module's Build.cs dependencies.
  Register descriptors with FLibraNativeNodes::Register in your module startup.
  Use the same type UUID, ABI version, numeric input order/widths, output width
  and signal branch count in C++ and the project's JSON node definitions.
  Parameter callbacks run on workers: do not touch UObject/actors there.
  Signal callbacks run only through explicit owner-thread DispatchSignal.
  State is caller-owned, zero-initialized and aligned for double; initialize and
  cleanup callbacks handle per-instance resources, including failed initialization.
  Descriptor contexts and callback code must outlive every program using them.
  Registration is append-only and transactional; hot module unloading/reloading
  is unsupported. Close the editor before rebuilding a node module.
  Blueprint can call the runtime; Blueprint implementations of nodes are deferred.
  Numeric input defaults are exposed to callbacks; arbitrary inspector property
  serialization, cyclic signal graphs and multi-target signal outputs are not.

Profiling and native feedback
  Core ProfilingHooks are optional. Empty hooks perform no clock reads or
  per-scope allocations. ProfileRecorder provides engine-independent cumulative
  call counts, inclusive/exclusive time and minimum/maximum in nanoseconds.
  ConfigureRecording enables UE's independent recorder; ConfigureProfiling
  controls optional node/accessor detail. Reconfigure only while evaluation and
  signal dispatch are idle. UE Insights is an optional parallel sink, not required.
  Connected peers explicitly advertise engine, role and capabilities. Editor,
  runtime and viewer roles do not imply asset catalog or profiling support.
  Protocol 3 peers advertising profiling/values accept bounded LFXP Control frames
  and send complete paged profile snapshots and bound native values back to the
  editor. No recursive graph walking is used to retrieve watched values.
  View > Native preview profiler displays complete snapshots and native returned
  values, with explicit ns-to-ms conversion. Partial pages are not complete data.
  MCP exposes libera_preview_clients, libera_preview_telemetry,
  libera_preview_profile_control, libera_preview_watch_values and the undoable
  libera_graph_set_parameter. Controls being sent is not an engine acknowledgement.
  Capture intervals are 100..5000 ms. Up to 64 node UUIDs may be watched.
  Asset catalog/metadata exchange is not implemented by these capabilities.

Engine task and rendering boundaries
  FLibraTaskScheduler owns UE Tasks, prevents replacing running jobs and joins
  before Core instance storage is released. Submit/wait belong to one owner thread.
  FLibraRenderDispatcher snapshots borrowed command/vertex/index buffers on GT,
  then calls ILibraRenderBackend on UE's render thread. Oversized snapshots leave
  Core buffers intact. Completion means backend submission, not GPU completion.
  The default snapshot budget is 16 MiB. Mesh/material resolution and a concrete
  GPU particle backend remain separate work; this interface is not a renderer.
  Vector arithmetic uses double-precision SSE2 on x86/x64, NEON on ARM64 and a
  scalar fallback, preserving active lanes and interpreter error/write order.
  MSVC and ClangCL native tests passed. ARM64 execution remains unverified.
  Native CMake LIBERAFX_MATH_FORCE_SCALAR disables SIMD for fallback validation.

Explicit local automation (disabled by default)
  LIBERAFX_MCP_DEBUG=1 enables the editor's current-user-only named pipe
  LiberaFx.Editor.Debug.<PID> for local credential bootstrap. Credentials remain
  in process memory; never persist them in scripts, logs, source or config.
  LIBRA_AUTOMATION_PREVIEW=1 enables an independent transient EditorPreview world
  in the UE editor module, without modifying the user's level or requiring PIE.
  Set LIBRA_PREVIEW_PORT, LIBRA_PREVIEW_TOKEN and LIBRA_PREVIEW_FINGERPRINT in the
  launched UE child's environment using the paired editor session. Host is local.
  These opt-ins are for local validation, not production asset discovery.

Optional example project plugin
  From this repository, copy Runtime\Integrations\Unreal\Examples\LibraProjectNodes
  into your project's Plugins directory.
  Its native parameter Scale and signal Route match
  Runtime\examples\CustomNodes\CustomScale.json and CustomRoute.json in this repo.
  Copy those JSON files into the editor project's configured NodeDirectory.
  Runtime\examples\Graphs contains matching graph fixtures.
  The example module registers its descriptors before default-phase asset loads;
  it does not add project-specific types to the editor's always-visible Core list.
