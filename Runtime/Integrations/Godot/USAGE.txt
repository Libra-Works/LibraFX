LIBERA FX for Godot 4.7
======================

Prepared/shared simulation: call player.prewarm_package(bytes, capacity, workers)
from an in-tree player during loading. Normal play_package reuses the matching
prepared pool. Normal _process gathers independent players into a shared bounded
executor; explicit advance(delta) stays immediate. Exhaustion does not allocate
another host. See source SDK docs/runtime-shared-simulation.md for limits.
Nested Spawnables and Core procedural mesh emitters support prepared/shared
playback. Native projectNodes() may return policies/policyCount separately from
descriptors. reusable, workerSafe and parallelPreparation are independent;
undeclared callbacks stay on the caller thread after workers join and cannot
be pooled. Rebuild project modules with the matching SDK.

This Windows x86-64 GDExtension embeds the same portable C++ Core Runtime
used by the other integrations. New .lfxb exports contain the existing LFXP
Spawnable package envelope, including scalar-only roots. Legacy raw .lfxb
programs and the legacy .lfxp package input alias remain supported. No
.NET runtime is required in Godot.

The godot-cpp build profile enables JSON, Node3D/World3D, Mesh/ArrayMesh,
MultiMesh and RenderingServer APIs used by the adapter. CPU package Draws,
CPU Sprite particles and Flexible Plane use owned RenderingServer instance
and MultiMesh RIDs rather than per-draw scene-tree render Nodes. The effect
player and its root/child Node3D transform/visibility scopes remain. GPU
submission retains its existing path. CMake links godot::cpp; no separate
graphics SDK library is required.

Build from an x64 Visual Studio developer shell with CMake, Ninja, Python,
and a separate godot-cpp checkout that provides the 4.7 API:

  cmake -S Runtime\Integrations\Godot -B C:\LiberaBuild\Godot -G Ninja -DCMAKE_BUILD_TYPE=Release -DGODOT_CPP_DIR=C:\src\godot-cpp
  cmake --build C:\LiberaBuild\Godot

Copy liberafx.gdextension and bin\liberafx_godot.dll into your Godot project
with that relative layout; open the project in Godot to discover the
extension. Add a LibraEffectPlayer node. Keep .lfxb and .lfxp files under
res:// (include both extensions in the Godot export preset's non-resource
file filter). A packaged game does not need the .lfxproj, the Converter, or
a copy of godot-cpp.

Convert graphs offline using the authoring repository:

  dotnet run --project Tools\Converter -- convert path\input.lfxproj path\effect.lfxb

Play exported .lfxb from GDScript on the main thread after the player has
entered the tree. play() routes by the LFXP signature to package playback;
legacy raw LFXB still uses standalone playback. The file suffix does not bypass
either loader's validation:

  var result: int = $LibraEffectPlayer.play(FileAccess.get_file_as_bytes("res://effect.lfxb"))
  if result != 0:
      push_error("LIBERA FX could not play the effect: %d" % result)

The player advances automatically with Godot's process clock. For deterministic
stepping, call set_process(false) after play and then advance(delta_seconds).
play and advance return numeric Core Result codes (0 = Ok; see
Runtime\include\liberafx\LbRuntimeResult.h). An optional duration in seconds
limits playback; the default -1 runs until stop or scene removal. A failed
play call preserves the current effect. Each player owns its own storage.
read_value(node_uuid) returns the evaluated lanes as PackedFloat64Array, or
an empty array if the player is stopped or the UUID has no value. Use these
values to drive Godot properties from your scene script.

The explicit package-only entrypoint also accepts the canonical .lfxb bytes
or legacy .lfxp bytes:

  var package := FileAccess.get_file_as_bytes("res://effect.lfxb")
  var result: int = $LibraEffectPlayer.play_package(package)
  if result != 0:
      push_error("LIBERA FX package could not play: %d" % result)

The package is loaded and validated before replacing current playback. The
player advances its Spawnable lifecycle, children, routing and timing on the
Godot main thread. An optional duration uses the same -1 / finite-seconds
convention as play(). Legacy raw LFXB playback remains unchanged; do not pass
raw bytes to play_package(). Renaming a file does not convert its contents.
New scalar-only exports use package lifecycle behavior, not standalone lifetime
semantics. Existing raw fixtures are intentionally unchanged.

Focused coverage added to Tests/package_smoke.gd checks both explicit package
playback and unified play(), rejects truncated LFXP without replacing playback,
and retains the existing callback-driven replacement with raw LFXB. No build,
Godot execution or rendered-pixel validation was performed for this change.

Named Game I/O is available for packages:

* get_game_io_ports() returns dictionaries with name, kind, kind_name, width
  and is_color. Kinds are input_property, input_signal, output_property,
  output_signal and owner_matrix.
* set_game_property(name, PackedFloat64Array) and fire_game_signal(name)
  return Core result codes. set_owner_matrix(PackedFloat64Array) supplies a
  package's owner-matrix input.
* dispatch_signal(node_uuid) dispatches an authored root Signal node by UUID;
  it is separate from the named Game I/O signal input.
* Connect to game_io_event(event). The event dictionary contains name,
  kind/kind_name, container_id, instance_id (decimal string), is_color and
  values (PackedFloat64Array). Events are emitted on the main thread while
  advancing; an input signal's resulting events are drained on the next
  advance. Root names use root package port metadata; child names are resolved
  through the matching container's port table, never through root indices.
* read_value(node_uuid) reads root-program node values for either playback
  mode. Spawned child instance values are not currently exposed by this node.
* get_render_stats() reports this player's current CPU package submissions:
  render_server_instances, cpu_multimesh_batches, opaque_model_multimesh_batches,
  opaque_model_multimesh_members, effect_scope_nodes and
  flexible_plane_surface_updates. `render_server_instances` counts the current
  direct/batched submission slots, including hidden or not-yet-populated
  entries; it is not a visible-pixel count. `allocated_render_server_instances`
  counts every currently owned valid instance RID, including any hidden or
  fallback RIDs. Its breakdown is `allocated_draw_instances`,
  `allocated_flexible_plane_instances`, `allocated_cpu_particle_instances`,
  and `allocated_opaque_model_batch_instances`. The separate
  `allocated_render_server_multimeshes` counts owned MultiMesh RIDs, not
  instances. These CPU-renderer counters exclude GPU adapter resources.
  At present, batching releases the individual fallback instance RIDs; the
  counters are measured separately rather than assuming this is always true.
  The cumulative CPU transfer counters are
  cpu_multimesh_buffer_uploads, cpu_particle_active_records,
  cpu_particle_records_transferred and cpu_particle_bytes_transferred.
  Active records sum live particle counts across uploads; transferred records
  and bytes count the entire capacity-sized submitted buffers, including
  padding (16 floats per record). These counters do not imply a speedup.

ModelDraw and SpriteDraw/SpriteAnimation/SpriteComposition are supported by the
CPU package renderer using explicit in-memory Godot resource bindings:

  $LibraEffectPlayer.set_mesh_binding(
      "/Engine/BasicShapes/Cube.Cube", BoxMesh.new())
  $LibraEffectPlayer.set_texture_binding(
      "/Game/FX/T_Atlas.T_Atlas", preload("res://atlas.png"))

Each identity must exactly match the draw's compiled `assetPath`. Bindings
must be set while stopped; a missing/invalid resource rejects play_package and
preserves current playback. Godot does not load assetPath values or substitute
placeholder resources. Root and spawned-child draws retain separate Node3D
effect scopes and use owned direct RenderingServer RIDs rather than per-draw
MeshInstance3D Nodes. Compatible opaque ModelDraws sharing the same Mesh
resource can share one MultiMesh across root and child scopes. Eligibility is
conservative: all surfaces must have opaque, non-billboard StandardMaterial3D
materials without next passes; per-draw overrides and parameters are excluded.
Special depth, refraction, alpha-antialiasing, render-priority, fixed-size,
particle-trail and opacity-producing flags are also excluded.
Transparent, unknown and custom-shader state stays in separate instances.
Each member must also have a finite, positive effective world-transform
determinant. Mirrored, singular and nonfinite transforms stay on separate
instance RIDs so Godot can apply per-instance culling behavior. Materials and
transforms are rechecked while held, so incompatible changes fall back to
separate RIDs. A ModelDraw retains its
bound Mesh resource and makes an effect-owned Mesh copy only when surface
material overrides/uniforms need isolation. Surface slots, texture uniforms,
per-draw shader parameters, and the bound asset remain separate. Each sprite
uses an effect-owned centered QuadMesh, unshaded alpha StandardMaterial3D,
the explicitly bound Texture2D, and per-draw tint and atlas UV state.
Draws are not merged across material or uniform state, and transparent order
is not changed by a custom batching step.
Position, rotation, scale, tint, frame
and other numeric sprite inputs are read from the root or matching child
instance, not from shared/root values. SpriteDraw and SpriteAnimation use
their atlas settings and the native flipbook sampler; SpriteComposition uses
the native composition sampler, scope-local elapsed time, cell-sized quads,
keyed transforms and Godot material render priority. SpriteDraw/SpriteAnimation
billboarding is enabled by the authored setting. Rotation is applied as
Godot-local Euler degrees. Direct instances synchronize their composed scope
transform, scenario and visibility even while the player and SceneTree are
paused. The nearest Node3D ancestor of the playback Node supplies the owner
transform and visibility across the intervening non-spatial playback Node.
Leaving the scene tree still stops playback. The root scope is named
`LibraFxRootScope`; a
replacement started before the previous queued scope is freed receives a
`LibraFxRootScope_<n>` name to avoid ambiguous siblings.

Flexible Plane Draw is supported in this package renderer for
root and spawned-child scopes. Bind its compiled texture identity explicitly
with set_texture_binding before playback; a missing or invalid texture rejects
the package. Each draw owns one ArrayMesh and direct RenderingServer instance
with an unshaded transparent, vertex-colored StandardMaterial3D. Camera-facing
ribbons require the player camera_path Camera3D or, failing that, the active
viewport Camera3D. The debug player uses the viewport camera. History is shared
by draws of the same source within a scope, but never between root and child
instances; backwards time clears it.
The native renderer exposes resetFlexibleHistories() for hosts implementing
explicit discontinuous seeks. Normal player/debug advances are nonnegative;
no public forward-seek API is provided here. Rendering failures are reported
and hide the affected scope instead of leaving a stale ribbon visible.
Visibility, owner transform and world scenario are synchronized to its owned
RenderingServer instance. The playback Node3D scopes are retained; Flexible
Plane adds no scene-tree Node.
Geometry and byte buffers are reserved once per effect instance and stay
bounded by the descriptor's list (up to 64 points) or history capacity (up to
4096 points); one dynamic ArrayMesh surface is updated in place.

ModelDraw supports surface overrides bound while stopped with
set_material_binding(compiled_identity, Material). clear_material_binding
removes the registration. Each material slot addresses the zero-based mesh
surface. Global scalar/vector/texture parameters require a ShaderMaterial with
a matching named float, vec4/color or texture uniform. Texture parameter
identities are bound with set_texture_binding; an empty texture identity
leaves the shader default unchanged. A draw with parameter overrides gets
its own material copy, so child values cannot change a sibling, the root,
or the original Godot resource. Unsupported material-layer associations or
sprite material overrides are rejected rather than ignored.

SpriteComposition draw order must fit Godot's render-priority range 0–127.
Other render node kinds and debug draw are rejected. CPU-only packages
without render payloads remain supported.

GPU package playback
--------------------

The LGPK particle interpreter uses the global RenderingDevice on the render
thread for supported root and Spawnable child emitters. Root GPU emitters require
AutoDestroyWhenIdle to be disabled, as in Unity. Godot validates packaged
Unreal-format LGPK v1 packets and runs the trusted embedded compute interpreter
(opcodes 0–41, up to 128 registers); shader source from a package is never
executed. A trusted GPU publication pass writes a five-texel-wide RGBA32Float
state texture, sampled directly by the billboard vertex shader. Normal
simulation and drawing do not read particles back to the CPU or rewrite
per-particle instance transforms. One MultiMesh draw per emitter contains
fixed identity instances; the shader discards dead particles. The extra state
texture uses 80 bytes per capacity slot, in addition to the 80-byte particle
buffer. Aggregate live capacity remains limited to 16384 slots per player.
Because positions remain on the GPU, emitter draws bypass CPU bounds culling;
this trades additional vertex work for removing synchronous state readback.
Dispatch currently synchronizes main/render-thread command processing, not a
local device submission. This is not a performance guarantee for every effect.

Version 2 GPU manifests may mix those existing particle programs with
Fluid2D programs. Godot validates every scope, identity, settings block and
`builtin:fluid-alpha` renderer before allocating native resources. Fluid2D
uses the trusted generated Fluid2D shader source on the global RenderingDevice
and keeps its seven simulation fields and RGBA16F output on the GPU. The output
is sampled directly by Godot through Texture2DRD and a premultiplied-alpha
spatial material on a local XY plane; the fluid fields are not read back for
presentation. A shared per-effect Node3D scope tracks the nearest spatial
owner's full world transform and visibility. Each fluid uses a
RenderingServer instance RID (not a per-fluid scene Node or MeshInstance) and
its exported 4x4 affine Draw Matrix, including translation, rotation, scale,
and out-of-plane orientation. Like the existing GPU particle path, an exported
Draw Matrix is authoritative world-space data and is applied as-is, not
multiplied by the spatial owner's transform a second time. Without exported
Draw Matrix rows, the plane follows the nearest spatial owner's world transform.
The plane measures
domainWidth*sizeScale by domainHeight*sizeScale and is centered on its local
origin. The logical fluid grid is Y-up; the spatial material maps its output
so positive source Y and buoyancy travel along local +Y. Stop, Destroy, reload,
world removal and owner visibility changes synchronize or clear the relevant
instance and native RIDs.
At most 16 fluid programs may be active for one player. Unsupported renderers,
invalid settings and devices unable to provide the required storage/sampleable
RGBA16F texture fail visibly through `get_gpu_error()`.

Optional settings.vorticity (0..100) reinforces existing rotation using
neighboring advected velocities. The force is applied every substep before
pressure projection; it is separate from noise-driven turbulence. Old settings
omit it and use zero. Nonzero exports require the updated extension. The
uniform block is 512 bytes; vorticity remains in grid.w, with model/reaction/force vectors appended.
Tests/fluid_2d_vorticity_smoke.gd uses the compiler's fluid-only.lfxb and
vorticity.lfxb fixtures with LIBERAFX_GODOT_TEST_HOOKS enabled. It compares real
GPU velocity fields, closed boundaries, independent retirement and restart.

Both GPU paths require a RenderingDevice renderer such as Forward+ or Mobile.
Compatibility and headless/null devices are rejected; there is no CPU fluid
fallback. Fluid output requires a 3D World3D/viewport and camera for visible
presentation. GPU particles and fluids now use the same global device, but
generic cross-container field bindings are still separate implementation work.

Version 3 GPU manifests add same-scope generated Texture2D bindings from a fluid
producer's DyeOutput to a particle billboard. These references appear separately
from resourceAssetPaths and require no set_texture_binding call. The shared
RenderingDevice output is sampled through Texture2DRD; no field readback is
used for this binding. The source is created and advanced before its consumer.
An optional automaticPlane=false suppresses the source's separate plane while
retaining compute and output storage; the editor uses this by default when the
output is consumed. Each scope resolves its own producer and releases both
resources with that scope. Other field outputs and particle field sampling are
not provided by this binding. Tests/fluid_2d_generated_smoke.gd consumes actual
generated-output.lfxb and fluid-only.lfxb compiler fixtures, with test hooks,
to check consumer pixels, orientation, independent retirement and clear replay.

Each spawned instance owns its particle state and advances on its local time.
Draw Matrix rows are read from that same scope and affect only billboard
placement and bounds. Simulation remains emitter-local. The initial limits
are 16 emitters per scope and 16,384 active particles per player. The default
emission rate is 100 particles/second; set gpu_spawn_per_second to change it.
FlowMap2D uses the same explicit set_texture_binding API. Supply readable
linear RG data. Godot snapshots the base mip at admission and filters it
with linear clamp on the GPU. The per-player FlowMap budget is 32 MiB.

Local preview and execution debugging
-------------------------------------

Add a dedicated LibraEffectPlayer and a Node with liberafx_live_preview.gd.
In the editor's Preview Connections window, copy the manual invitation and
the public TLS certificate. Pass them to the script's
connect_local(player, invitation_json, public_certificate_pem). Keep the
invitation private. The helper connects only to the loopback editor over
WSS and checks the certificate fingerprint. disconnect_preview() clears the
session baseline and stops its playback, not independently started effects.

connect_local evaluates standalone LFXB v1/v2 at editor-published
times. Use read_value() for the evaluated values and get_preview_error()
for the latest compile error. For package rendering, keep
liberafx_package_preview.gd beside the transport script and use
connect_package_local with an idle player and the required resource
bindings. See LIVE_PREVIEW.txt for the timeline and editor-command limits.

For standalone breakpoints on Windows, add a LibraFxDebugPlayer and call
start_debug(lfxb_bytes, editor_debug_invitation). This invitation is distinct
from the preview connection invitation. Use advance(delta) to submit one
step at a time; poll() reports busy, closing, closed, active, result, time
and debug_transport_active. Read values with read_value(node_id) after a
successful step. Call close() and poll until closed to stop without waiting
in the main loop. The evaluator runs off the Godot main thread.

For package debugging, configure the same mesh, texture and material
bindings on LibraFxDebugPlayer, then call load_package(lfxp_bytes). Select root
with container_id="" and instance_id=0, or obtain a child identity by
advancing and reading next_package_event(). Use the current
get_debugger_generation() and a fresh execution debug invitation with
attach_package_debugger(generation, container_id, instance_id, invitation).
Call poll() regularly to present completed jobs. While a worker is paused,
the scene keeps the last committed render state. Wait for an idle job before
reading package values or dispatching signals.

To exercise a real editor breakpoint on Windows, copy
Tests\breakpoint_smoke.gd beside the DLL in the scratch project. Run with
isolated LIBERAFX_DATA_ROOT and Godot user data:

  dotnet run --project Tests\CommentImageSmokeTests.csproj -- --godot-breakpoint C:\Godot\godot_console.exe C:\LiberaBuild\Smoke

The test uses the editor's execution debug service and requires an authored
root breakpoint to pause a real Godot worker and checks that its scene stays
visible before sending Resume.

The Current Camera graph input is connected only when the package contains
the reserved hidden input-property port "__LFX_CAMERA_V1" with width 4. Before
each root advance (including the first), the player writes [x, y, z, 1] from
the selected Camera3D global position in Godot world units, or [0, 0, 0, 0]
when no camera is available. Set the player's camera_path NodePath to choose
an explicit Camera3D; otherwise get_viewport().get_camera_3d() is used. A
deleted, unresolved or non-Camera3D override falls back to the viewport
camera. If neither source yields a Camera3D, the zero/invalid sample is used.
Packages without that exact reserved port are not camera-probed or modified.

CPU particle Sprite billboards
------------------------------
CPU packages use LFXP format 4/package 12 with `cpuParticleVersion: 1`.
Template CPU systems or nested Spawnables use format 5/package 13.
For either format, bind
each `cpuParticles` entry's `assetPath` with `set_texture_binding`, except for
the explicit `builtin:white` token. Each CPU emitter owns one RenderingServer
MultiMesh RID and one direct instance RID, with no MultiMeshInstance3D Node. It
reuses a packed upload buffer, grows its capacity geometrically, and uploads
per-particle transforms and RGBA in one MultiMesh buffer transfer per populated
emitter update. The material billboards per view while retaining separate X/Y
sizes. Alpha and
Additive are supported; transparent sorting is by emitter, not by particle.
`drawScale` applies to effect-local position and XY size.

On the main thread, call `pop_cpu_particle_event()` until it returns an empty
dictionary. For automatic playback, connect `cpu_particle_events_ready` and
drain synchronously there, including before a duration-limited playback ends.
Kind 1 is Property and kind 2 is Signal. `particle_id` is an unsigned decimal
string and `values` contains `width` values. At natural completion, polling
may still drain the queues; the completed host is released only after all root
and scoped CPU queues are empty.
Explicit Stop or replacement releases that queue, so drain beforehand. The
renderer does not consume events; size the queue for one simulation advance.

CPU Sprite rendering supports root and nested Spawnable scopes. Each dynamic
instance owns its MultiMesh and instance RID; Life Time stops emission but keeps
rendering alive until that scope's particles and descendants finish.
Use pop_scoped_cpu_particle_event(container_id, instance_id) for a child queue;
pop_cpu_particle_event() remains root-only and cannot discard child events.
The production-extension regression Tests/nested_cpu_render_smoke.gd consumes
LIBERAFX_HIERARCHY_FIXTURE (the compiler nested-cpu-only-retention package).
It checks real pixels after both parent/child deadlines, natural cleanup and
restart. LIBERAFX_HIERARCHY_OUTPUT optionally selects an evidence directory.

For the CPU direct-submission smoke, copy the isolated
`cpu-particles.lfxb` fixture to the scratch project as `cpu-particles.lfxb`,
copy `Tests\cpu_render_submission_smoke.gd`, and run:

  --headless --path C:\LibraBuild\Smoke --script res://cpu_render_submission_smoke.gd --quit-after 120

The script reports direct-instance, MultiMesh batch, bulk-upload and
transferred-record counts, checks that no CPU render Nodes were added, and
checks Stop cleanup.

Godot RID migration verification
--------------------------------
The migration was built against the pinned Godot 4.7 godot-cpp API and run
with Godot 4.7.2's console executable in an isolated scratch project. The CPU
fixture reported one direct instance, one CPU batch, two uploads, six active
records, eight submitted capacity records and 512 submitted bytes.

An earlier Flexible Plane fixture mistakenly replaced a child template rather
than the root; the earlier headless result did not verify plane updates.
The corrected fixture targets the root and the headless test now requires two
actual plane surface updates. Real graphics checks with the Windows OpenGL
compatibility renderer on an AMD Radeon RX 6700 XT captured CPU Sprite and
fixed-point plane pixels, their held/paused owner movement, hide/show, world
swap and Stop. A red-to-green plane gradient checks the dynamic attribute data.
The world-swap test retains the prior World3D while switching. On this Godot
4.7.2 build, dropping the only old World3D reference during a SubViewport swap
also emitted `scenario_remove_viewport_visibility_mask: scenario is null` in
`Tests\world_swap_control_smoke.gd`, which does not load the extension.
The real graphics test also checks an opaque root/child batch alongside a
separate transparent draw, and verifies that a deliberate camera-facing
plane failure hides all scope entries until a valid update recovers.
The determinant regression uses an actual one-sided triangle and compares the
framebuffer against separate direct instances. On that same OpenGL setup, the
old mixed-parity batch dropped 820 mirrored pixels; the conservative fallback
matches the direct image pixel-for-pixel. Positive-parity batching also matches
its direct baseline. The headless determinant check additionally covers zero
determinants, mixed batches, draw-local scale and double reflections.

Development: water, combustion and generated fields
--------------------------------------------------
The source now defines Smoke, FreeSurface, ShallowWater and Combustion models.
Use matching regenerated trusted shaders (512-byte uniforms, 13 kernels).
The model defaults preserve old Smoke settings. Water uses a bounded 2D CFL
step; ShallowWater is flat-bed first-order HLL depth/momentum and has a depth
safety cap of 16 * rest depth. FreeSurface uses staggered face velocities,
air pressure zero, pressure warm starting and conservative water-fraction
transport. Combustion stores fuel/temperature/smoke/reaction, with ignition,
heat release and cooling; its dedicated fire display does not replace reaction.

The dedicated water renderer adds Fresnel, foam and surface lighting; shallow
water uses a GPU-displaced horizontal grid. Fire visualizes temperature emission
and smoke. These development paths need their own numerical and framebuffer
acceptance; earlier smoke evidence does not certify them.

Instance-owned output allocations: DyeOutput RGBA16F premultiplied display,
ColorOutput RGBA16F straight display, FieldOutput RGBA32F local velocity.xy,
density/depth and temperature. VelocityOutput/DensityOutput are typed views
of FieldOutput, without copies. Storage is 144 bytes/cell before overhead.

Version 3 generatedDrawBindings connect same-scope fluid outputs to ordinary
Sprite/Flexible Plane main textures (ColorOutput only) or explicitly bound
material texture parameters. The compiled builtin:generated-texture marker
requires an executable producer reference. It is not an engine asset fallback.
Each instance resolves its own output; prepared definitions do not retain a
native texture from another instance. Bound drawing consumers suppress the automatic
source plane unless authored otherwise. Static asset references remain distinct.

FlowMap2D FloatVelocity reads raw RG. FloatDensity reads BA (density and
 temperature); SignedNormalized retains the old RG*2-1 behavior. GeneratedPlane
coordinates use the producer plane transform and convert velocity into consumer
simulation space. Source and consumer matrices must be invertible. Sampling
clamps at the edge. Particle comparison opcodes 42/43 implement scalar float
GreaterThan/LessThan, so density masks/probabilities can set Alive on the GPU.
The LGPK packet envelope remains version 1; older interpreters reject new ops.

Cell forces support up to eight ordered, explicitly connected nodes:
Acceleration, Noise, CurlNoise, CellPosition, Time, Density, Temperature, Add,
Multiply, Sine and Smoothstep. InputA/InputB refer to earlier stable node IDs;
noise uses them as position/time, math uses vector inputs. Final unconsumed
math/noise/acceleration outputs contribute force, source nodes alone do not.
Noise is evaluated per cell on the GPU; density and temperature masks do not
require normal playback readback. Vorticity is a separate neighborhood force.

Current engine acceptance targets remain Windows D3D11/SM5 (Unreal 5.7),
Unity 7000-series D3D11 Built-in fallback, and Godot 4.7.2 Vulkan Mobile/Forward+.
UE 5.8/5.9 are separate tracked compatibility work, not proven by UE 5.7 runs.
