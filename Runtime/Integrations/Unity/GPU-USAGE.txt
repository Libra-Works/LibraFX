Libra GPU particle adapter

Fluid2D in Spawnable packages
-----------------------------
An authored 2D smoke/ink GPU container is played by the existing Spawnable
component, in root and spawned scopes. No additional component, renderer or
per-fluid GameObject is required. Version 2 GPU executable payloads can mix
particle programs and FluidPrograms; particle programs retain their existing
explicit Unity bindings. The fluid renderer must be builtin:fluid-alpha.
The package includes the fixed LibraFluid2D.compute, its .meta, the
LibraFluid2DResources asset, and LibraFluid2DDraw shader. Keep these together:
the Resources asset explicitly references the shipped compute asset for player
builds. No shader source from a fluid package is compiled or executed.

Each live scope owns separate compute buffers, compute-shader instance, output
RGBA16Float texture and draw resources. The simulation requires compute support
and RGBA16Float load/store. Unsupported hardware and missing assets fail
preflight. The output is premultiplied and drawn as a local XY quad with
domain dimensions times the exported sizeScale. A connected GPU draw Matrix
is a world-space override; otherwise the plane follows the effect owner.
OwnerMatrix is an explicit host-supplied input via SetOwnerMatrix, not an
automatic copy of the owner Transform. Play/Stop and scope events own its lifetime;
Stop removes the draw and retires queued GPU resources. Delta is capped at
maximumStep * maximumSubsteps; excess is discarded. Zero delta does not inject
or advance. SourceEnabled disables both density and velocity injection.

LiberaFxSpawnableComponent.TryGetFluidOutput(nodeGuid, instanceId, out texture)
exposes the native RenderTexture for the live root (instanceId 0) or child
scope. It is borrowed and becomes invalid when the scope stops; do not destroy
or retain it. TryGetFluidStats reports the latest substep count and discarded
delta. No synchronous readback occurs during normal playback.

Editor/Tests/LibraFluid2DVerification.cs is a graphics-enabled executeMethod
check. Set absolute LIBERAFX_DATA_ROOT, LIBERAFX_FLUID_UNITY_OUTPUT and
LIBERAFX_FLUID_SETTINGS paths in a dedicated project. On Unity 7 alpha's
built-in pipeline use -force-d3d11 -enable-builtin-rp-fallback. This check
reads back the fixed shader on a non-square grid, exercises odd/even pressure,
independence, boundaries, source disable, reset and disposal, and captures an
actual transparent quad without a diagnostic primitive. It does not substitute
for exercising a compiler-produced Spawnable package or platform/player builds.
RunOrientation additionally consumes LIBERAFX_FLUID_FIXTURES/fluid-only.json
and checks actual framebuffer centroids: low sourceY is at the bottom, and
positive sourceVelocityY and positive buoyancy independently raise the plume.
Its initial/risen captures contain the fluid quad only. Raw compute output
is sampled with logical V increasing along local +Y (not a camera-texture flip).
RunPackage consumes LIBERAFX_FLUID_PACKAGE and LIBERAFX_FLUID_NODE_ID and
verifies the actual compiler LFXP importer, root Play/advance/zero-delta pause,
framebuffer, Stop and blank restart. RunNestedPackage checks native Spawn,
authored two-second child lifetime completion, restart and Stop.
RunCompiledScopes uses LIBERAFX_FLUID_FIXTURES containing fluid-only, mixed
and nested JSON plus mixed.lfxb, imports its actual particle shader/metadata,
and plays the mixed LFXP with both GPU backends. All use the same isolated
output variable. The continuous root fixtures require AutoDestroyWhenIdle=false;
this is the existing GPU lifecycle policy, not a fluid-specific workaround.
These checks passed on Unity 7000.0.0a16 / D3D11, including a 23x37 package,
24x40 GPU readback, and independent upward velocity/buoyancy framebuffer
centroids. Other graphics APIs, URP fluid rendering and player builds remain
unverified. Existing particle and direct-render regression checks also passed.

Particle adapter
----------------

Export both CompiledGpuProgram.EmitUnityCompute().Text as a .compute asset and
ExportMetadataJson() as a .json asset. Import both together. The adapter does
not load or require the .NET 10 compiler in Unity. The built-in Unity
jsonserialize module, compute shaders and GPU instancing are required.

Create a material using Libra/GPU Particle Billboard and enable GPU instancing.
Add LibraGpuParticleRuntime and assign the compute shader, metadata, material,
and one Texture2D binding for every exported resource ID. FlowMap2D uses the
same Texture2D binding path. Every resource must have an explicit non-null
Texture2D; unresolved/null bindings are rejected instead of silently
substituting white. Play On Enable configures and starts automatically.
Flow maps sample RG and decode [0,1] to [-1,1]. Float2 inputs are UVs; Float3
inputs use the resource's configured world-axis pair and bounds. Any Texture2D
can be assigned; disable sRGB for vector data when possible. The runtime binds
each flow-map texture only to compute kernels that reference it. Flow-map
sampling is bilinear and clamps at the edge, independently of the texture's
filter and wrap settings. Regenerate and reimport existing compute assets to
pick up the sampler change.
Assets/Libra GPU/Reimport generated shaders and metadata reimports selected
assets after editing. In the Editor Configure checks the actual compute source
SHA-256 against sourceHash; deployed builds cannot inspect source and must
ship matching generated assets together.

Code can call Configure(shader, metadata, material, bindings), StartSimulation,
StopSimulation, ResetSimulation, Step(deltaTime, start, count, position, camera)
or StepCircular for a wrapping spawn range. Spawnable scopes instead use
ConfigureForSpawnable and StepSpawnable; that API disables automatic Update
simulation and retains fractional spawn progress per owner instance.
Reconfigure creates and clears new storage and stops automatic simulation; call StartSimulation explicitly to
resume. A failed configuration leaves the prior program intact. Reset is the
only in-place clear. Dispose/OnDisable release ownership. Previously submitted
draws retain their buffers through the next frame; on platforms supporting
pollable async GPU fences retirement also waits for the fence. Otherwise Unity
owns native GPU command/resource lifetime after frame submission. A pending
retirement count is exposed for diagnostics.

Particles are simulated on the GPU only. ReadbackForDiagnostics is explicit,
synchronous and must not be used in a normal frame loop. The status
RuntimeExecuted and dispatch/draw counts describe this runtime, not source
export. Capacity is fixed by the export; all particles are Update candidates,
and generated kernels skip dead particles. Flow compute dispatch order is
preserved. Unity's queued billboard draws must be terminal: metadata placing a
compute step after a render step is rejected. RenderStartTexture, ComputePass,
StorageTexture2D/Buffer resources, other ABI versions/strides, and non-64-thread kernels
are rejected, not silently approximated. Draw bounds are configurable; enlarge
them if particles travel outside the default region.

The supplied billboard shader is unlit, alpha blended, supports HDR tint,
texture, per-particle size, rotation and color, and uses camera-facing quads.
It works with the built-in pipeline and was also exercised with Unity 7 alpha's
URP 17.7. Other render pipelines may require a compatible material/shader using
the same _LibraParticles 80-byte layout. Rendering is queued per camera by
Unity, not a headless or CPU renderer.

Tools/GpuFixtureGenerator is an isolated .NET 10 fixture exporter referencing
Gpu/LibraGpu.Core. It emits two separately compiled shader/metadata pairs. An
optional second argument accepts a frontend delivery bundle: its canonical IR
hash is checked, then recompiled into a UnityCompute shader and metadata pair.
Do not import a USF bundle's shader or metadata directly as UnityCompute.
Editor/Tests/LibraGpuVerification.cs contains a graphics-enabled executeMethod
test. It performs explicit diagnostic GPU readback, 1000 zero-managed-allocation
steps, render-target pixel checks, resource reconfiguration and error checks.
Editor/Tests/LibraGpuPlayModeVerification.cs is a separate bounded batch
executeMethod test for automatic component updates, camera rendering, hot
reconfiguration, disable/reenable, destruction and deferred retirement.
Editor/Tests/LibraGpuMathNoiseVerification.cs compares real GPU math and noise
outputs with the Core reference fixtures, including finite guards and curl
divergence. It also checks FlowMap UV and world sampling on the GPU using a
point/repeat texture to verify that those texture settings do not affect the
result. Generate those fixtures with:

  dotnet run --project Gpu\LibraGpu.Core.Tests -- --export <output-directory>

Copy noise.compute, noise.metadata.json, noise.reference.json,
noiseguards.compute, noiseguards.metadata.json, math.compute,
math.metadata.json, math.reference.json, flowmap.compute, and
flowmap.metadata.json into
Assets\LibraFXGPUValidation\Fixtures, then run the test's Run executeMethod.
Its particle uploads and readbacks are test-only, not production simulation.
