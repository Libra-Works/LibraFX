LiberaFx native Runtime -> Unity adapter
=====================================

Prepared/shared simulation: scene components prepare assigned effects in Awake
when Use Prepared Hosts is enabled. Call PrewarmEffect during loading for dynamic
assets. Configure Prepared Host Capacity before preparation; exhaustion is an
explicit error. A shared late-frame manager joins bounded simulation workers
before publishing rendering. Manual preview/debug paths stay immediate.
See source SDK docs/runtime-shared-simulation.md for eligibility and lifetimes.
Nested Spawnables and Core procedural mesh emitters support prepared/shared
playback. Project native nodes declare independent reusable, workerSafe and
parallelPreparation flags through ProjectNodeRegistry policies. Undeclared
callbacks stay on the caller thread and cannot be pooled. Their owner phase
runs after worker jobs join. Rebuild project modules with the matching SDK.

Separation (no Unity APIs in the C++ Core):
  canonical .lfxb (LFXP) -> owned native SpawnableHost -> package component
  legacy raw LFXB -> owned native Program -> Instance evaluates numeric ports
       -> one libra_evaluate P/Invoke fills cached POD arrays
       -> MonoBehaviour.LateUpdate applies effect-owned render data and matrices.
       -> one selected Built-in/SRP camera callback submits direct Graphics draws.
The C++ work/default buffers are NOT Unity GPU buffers. The engine adapter owns
Mesh allocation, capacity and upload on its main thread. Dynamic quad mode
reuses a four-vertex array and Mesh vertex buffer, changing it through
Mesh.SetVertexBufferData. Static atlas mode changes only MaterialPropertyBlock.
No managed callbacks per node, engine pointers, per-frame material clones or
native buffer pointers retained by C# are involved. Serialized Mesh, Material
and Texture references are the engine asset handles in this sample.

Build the native plugin
-----------------------
FlexiblePlaneDraw is wired into root and Spawnable render scopes, with a
separate history for each instance and point source. The Unity adapter uses
owned dynamic geometry and direct per-camera Graphics draws; it borrows the
bound material and supplies its texture through a property block.
In RenderAssets, bind the authored texture identity to its Texture and exactly
one defaultMaterials entry. That Material must expose _MainTex and multiply
the texture by vertex color. Camera-facing mode requires Camera.main.
Preview v2026.11.22 includes the prerequisite runtime/API changes. Disable root
AutoDestroyWhenIdle for an indefinitely running standalone ribbon/history, or
author an explicit lifetime.

Runtime CMake builds liberafx_native by default. Set LIBERAFX_BUILD_INTEROP=OFF
when only the static Core library is needed. LIBERAFX_BUILD_TESTS=ON also
includes the bridge ownership, alignment, evaluation and allocation checks.

Example Windows commands from the repository:
  cmake -S Runtime -B build\native -DLIBERAFX_BUILD_TESTS=ON
  cmake --build build\native --config Release --target liberafx_native liberafx_interop_tests
  ctest --test-dir build\native -C Release -R liberafx_interop_tests --output-on-failure
Use Debug for the test's MSVC shared-CRT allocation hook: it checks that 10,000
scalar evaluate/default/read cycles allocate or reallocate no native heap.
liberafx_runtime remains a static C++ library; only the bridge is a shared DLL.
Unix visibility must also hide symbols compiled into the static runtime.

Graph-authored ModelDraw Cube verification
-----------------------------------------
The older "Native cube sample" menu uses a handcrafted program. To exercise
asset-based node creation, project save/load and the actual graph compiler:
  Set LIBERAFX_DATA_ROOT to an absolute isolated application-data directory.
  dotnet run --project Tests\CommentImageSmokeTests.csproj -- --model-draw C:\isolated\cube-fixture
Use isolated build output when another editor/build is using the repository.
This writes Cube.lfxproj and Cube.lfxp. Open the former in LIBERA FX to inspect
the Color connection and the ModelDraw rotation/scale defaults.

After installing this Unity adapter and a Release native library in a dedicated
project, set LIBERAFX_VERIFICATION_PROJECT to that absolute project directory
and LIBERAFX_MODEL_DRAW_FIXTURE_DIR to the fixture directory. Run Unity with
-batchmode -quit -executeMethod LiberaFx.Unity.Editor.LiberaFxModelDrawVerification.RunBatch
(also use the rendering flags above where required; do not use -nographics).
The check renders camera pixels, writes Cube.Unity.png locally, and creates
Assets\LiberaFxModelDrawSample\Cube.unity with persistent package/binding assets.
It refuses to overwrite an existing sample folder. Reopen that scene and press
Play; VerifySavedScene is a separate guarded entrypoint for reloading it.

The sample's /Game/LiberaFxSamples/Cube.Cube is an explicit legacy lookup alias,
not a Unity asset path or a portable resource ID. CubeBindings maps it to
Unity's built-in Cube mesh and maps the material's Color input to _Color.
The Unreal verification binds the same sample lookup key independently.
There is no automatic cross-project asset-identity inference in this demo.

For independent material selection and a graph-authored white/blue animation,
generate another isolated fixture using --model-material-animation instead of
--model-draw. ModelDraw first selects the mesh, then assigns a standalone
material descriptor to slot 0, generating its Color input pin. Time, Cos and
LerpVector4 drive white at 0 seconds, blue at 2, and white again at 4.
Run LiberaFx.Unity.Editor.LiberaFxModelDrawVerification.RunMaterialAnimationBatch
with the same guarded environment variables pointing to this fixture. It checks
material values and actual camera pixels at 0/1/2/4 seconds without replacing
the renderer, and saves Assets\LiberaFxMaterialSample\MaterialPulse.unity.
VerifySavedMaterialAnimation independently reloads that scene and its embedded
package/bindings. The sample material key is explicitly mapped to a Unity
Material; its Unreal-shaped text does not imply Unity asset discovery.
Unlike the older Cube fixture, this graph references the actual Unreal engine
Cube path, /Engine/BasicShapes/Cube.Cube, so it can also be transferred directly
to the Unreal preview window in that project. Unity explicitly binds this key
to its own built-in mesh; no Unreal-to-Unity lookup inference is performed.

Unity installation (Unity 6000.0 package minimum; tested package reference baseline 6000.2.6f1)
----------------------------------------------------------------------------
Unity 7 alpha verification of these Built-In RP sample shaders requires
-enable-builtin-rp-fallback on the isolated Editor command line. A successful
shader compile without that fallback does not prove that Camera.Render drew.

1. Copy Runtime and Editor folders from this directory into Assets\LiberaFx.
   Keep both asmdef files: the runtime asmdef enables unsafe pointer pinning.
   No third-party packages, network service, scene synchronization or reverse
   P/Invoke needed. Minimal projects need the built-in
   com.unity.modules.jsonserialize module for the adapter's GPU metadata code.
2. Copy the native artifact into the appropriate Assets\Plugins folder:
     Windows x64: liberafx_native.dll (Release), e.g. Plugins\x86_64
     macOS: libliberafx_native.dylib, built for the target architecture(s)
     Linux: libliberafx_native.so, built for the target architecture
   In Plugin Inspector disable Any Platform and select matching platform/CPU,
   including Editor when desired. Do not import a Windows DLL as a macOS plugin.
   Windows requires the matching Visual C++ Redistributable; do not deploy Debug.
   Restart the Editor after replacing a loaded native plugin.
3. Use the GameObject > LiberaFx menu to create a cube, animated 4x4 atlas or
   dynamic quad sample. Editor code creates shared sample material/atlas assets
   only once. Enter Play mode. Native time -> scalar gain/default -> splat/color
   drives cube movement/color; the same time port drives sprite atlas frames.
   Dynamic mode also uses the native scalar output to deform the cached quad.
4. For new exports, use LiberaFxSpawnableComponent as described below, even
   for scalar-only root graphs. For legacy raw LFXB only, add LiberaFxRenderer,
   assign your Mesh/shared Material or sprite Texture, and drag the directly
   imported LiberaFxProgramAsset into Legacy Program. Existing .bytes TextAssets
   still work in Compiled Program; leave Legacy Program empty in that case.
   Do NOT rename a new LFXP package to .bytes or convert binary to text.
   Leaving BOTH program fields empty selects the bundled generated v2 sample.
5. Set node GUIDs to the compiled graph's output instruction IDs:
     Position: scalar X or Vector2/3/4 (XYZ used)
     Color: four components, already evaluated by native Core
     Atlas Frame: scalar, multiplied by Frames Per Second in this example
     Deformation: scalar height delta for the two top vertices (dynamic mode)
   Set Default Node/Input Slot/Component to a disconnected numeric input. Leave
   Default Node empty if unused. Sample gain is node ...0002, slot 1, lane 0.
   SetDefaultGain mutates that bound native default without reloading the graph.
   Numeric values applied to Unity floats must be representable as finite floats.

The supplied Atlas Unlit shader is a built-in-pipeline example. For URP/HDRP use
an appropriate unlit shader/Shader Graph with _Color, _MainTex and _AtlasRect:
  textureUV = _AtlasRect.xy + meshUV * _AtlasRect.zw
The adapter converts Core top-left-origin atlas rows to Unity bottom-left UVs.
It assigns sharedMaterial and a cached MaterialPropertyBlock, never .material.
Model meshes/materials are borrowed serialized Unity assets, not destroyed.
Owned quad meshes are destroyed on disable; native instances are released on
disable. Do not configure SetupCubeSample/SetupAtlasSample on an active object:
create an inactive object, add/configure its component, then activate it.

ABI and ownership
-----------------
LbInterop.h compiles as C or C++; cdecl exports use uint64 program/instance handles,
uint32 instance-local binding tokens, int32 result codes and fixed-layout POD.
LibraValue is 40 bytes; LibraAtlasFrame 20; LibraSpriteVertex 36.
Host ABI records are not wire overlays. The C header asserts every field offset,
size and alignment even inside a caller's pack(1) include; C# uses explicit
FieldOffset/Size/Pack and tests Marshal.SizeOf/OffsetOf during program creation.
LibraValue requires 8-byte alignment; atlas and sprite vertices require 4 bytes.
Their array strides remain 40/20/36 bytes: no 16-byte SIMD alignment is assumed.
Unity's position/UV vertex stream is explicitly packed to 20 bytes, with offsets
0/12. Sprite vertex position/UV/color offsets are 0/12/20, not SIMD vector offsets.
Native work/default buffers use a C++17 aligned allocator guaranteeing at least
16-byte base alignment on every platform, not ordinary heap alignment assumptions.
The allocator honors Program::workAlignment()/defaultsAlignment() dynamically,
including 32/64-byte custom state requirements; matching aligned delete is used.
Internal state offsets must independently obey the Core's state alignment rules.
No borrowed work-buffer API is exported; any future such API must explicitly
publish its required alignment and validate it. Never reinterpret packed wire
bytes, sprite colors or float3 vertex fields as aligned SIMD vectors.
For repeatable managed contract tests (no Unity assemblies or packages needed),
put the matching native DLL directory on PATH and run:
  dotnet run --project Runtime\Integrations\Unity\Tests\LiberaFx.InteropTests.csproj
The test calls Marshal size/offset validation and checks real batched POD results,
program retention, defaults, atlas/quad transfers and steady-state managed GC.
Optionally copy Tests into Unity too; its Editor-only asmdef adds
LiberaFx > Verify native ABI contracts. These are forward P/Invoke tests, not
GPU/Play Mode tests.
GUID bytes are compiler big-endian order, not Guid.ToByteArray() Windows layout.
The C# binding code converts canonical GUID text once during initialization.
Effect Age and Delta Time require instance.SetTimeContext(effectAge, frameDelta)
before each evaluation. The example renderer supplies its elapsed effect time
and Unity's Time.deltaTime; manual hosts must supply the actual game frame
delta rather than an internal scheduler substep. Instance Age is local to the
enclosing Spawnable; at the effect root it equals the root's elapsed time.
For a built-in Signal, cache new NativeSignal(nodeGuid), evaluate the instance,
then call instance.DispatchSignal(signal, time, instructionBudget). Each dispatch
looks up the node in its program; the cached identifier avoids per-call GUID
parsing and managed allocations. A positive budget is shared across all branches.
Branches execute in connection order, depth-first; an error or budget exhaustion
stops the remaining branches without rolling back effects already performed.
Check the returned NativeResult. Spawnable packages require a separate host
adapter; use `NativeSpawnableHost` or `LiberaFxSpawnableComponent` for LFXP.

Spawnable package playback
--------------------------
The single Unity `LiberaFxSpawnableImporter` owns `.lfxb` and legacy `.lfxp`.
It routes by signature and validates with the installed native runtime before
creating an asset. New `.lfxb` exports contain the existing LFXP package envelope,
including scalar-only roots; `.lfxp` remains an input alias. Both import as
`LiberaFxSpawnableAsset`. Raw LFXB imports as `LiberaFxProgramAsset` for the
legacy renderer instead. Corrupt/unsupported inputs and a missing/incompatible
native plugin produce an import error, not a placeholder asset.

Add `LiberaFxSpawnableComponent` to an object and
assign that asset, and assign a `LiberaFxUnityBindingAsset` created from
Assets > Create > LiberaFx > Unity Bindings. The binding asset maps opaque
render/material identities and GPU node GUIDs to project-local Unity Mesh,
Texture, Material, ComputeShader and metadata TextAsset references. Do not put
Unity paths into the effect package or infer Unity assets from Unreal paths.
Bind every asset referenced by the root and all templates before Play; missing
or unsupported bindings fail preflight before native OnStart or spawn events,
with the reason in `LastError`.

Package reimport keeps the existing "package" local asset ID; component/prefab
references and the separate binding asset's Unity resource references remain
intact. This does not migrate a raw-program asset into a package asset in place.
When replacing an old raw export with a new package export, import at a new path
and assign it to the package component; do not keep the old renderer reference.

Focused importer verification (not executed as part of this format change):
in a dedicated installed Unity project, set LIBERAFX_VERIFICATION_PROJECT to
that absolute project directory and LIBERAFX_UNITY_SPAWNABLE_FIXTURE to an
existing compiler-produced LFXP package (.lfxb or legacy .lfxp). Invoke
LiberaFx.Unity.Editor.LiberaFxUnifiedImportVerification.RunBatch with Unity's
-executeMethod. It uses a unique temporary Assets folder and deletes only that
folder. It checks both suffixes, legacy raw byte execution, stable package IDs,
prefab/binding/resource references after reimport, and corrupt-input rejection.
It does not establish rendered pixels or Play Mode behavior.

The component drives the shared native package host using Unity's scaled
`Time.deltaTime`, exposes Spawn/Stop/Destroy/Signal and named game-I/O events
to C# subscribers, and accepts game signals/properties through its API.
`playRate` scales effect time; the Delta Time graph node receives Unity's frame
delta unchanged. Setting playRate to zero or pausing Unity time holds lifecycle
time. Natural root completion follows `AutoDestroyWhenIdle`; explicit Stop
retires instances without natural Destroy.

Model Draw, grid/sequence Sprite Draw, every layered Sprite composition layer,
CPU particles and Flexible Plane use direct draws without MeshFilter,
MeshRenderer or rendering GameObjects. Meshes, materials and textures from
Unity bindings are borrowed; sprite quads, CPU particle geometry, flexible
plane geometry and GPU buffers are owned and released on finish/Stop/restart/
disable/destroy. Material parameters, texture bindings, per-effect tint and
atlas rectangles use MaterialPropertyBlock state; shared Material assets are
never mutated or cloned by the ordinary Draw/FlexiblePlane paths. CPU particle
snapshots come from the same native root/template instance that drives
lifecycle (no second CPU effect is created). Model material slots and exposed
scalar/vector properties are checked against the selected Unity Materials.
Sprite rendering requires the supported atlas properties; billboard sprites
require an enabled MainCamera before Play. Unsupported render features,
material associations or missing shader properties are rejected, not ignored.

Direct draws are submitted once per camera by `Camera.onPreCull` for Built-in
RP (`Graphics.DrawMesh`/`DrawMeshInstanced`), or
`RenderPipelineManager.beginCameraRendering` for SRPs (`Graphics.RenderMesh`/
`RenderMeshInstanced`); the adapter never registers both paths at once. Camera
culling masks/layers and mesh bounds are respected.
Compatible opaque submissions can instance only when mesh, submesh, material,
layer and every property-block value match exactly, the material enables
instancing, the shader does not disable batching, the device supports it,
and each transform has a finite, strictly positive determinant. Mirrored or
singular transforms and nonfinite determinants fall back to individual draws.
All other opaque states use a direct draw. Transparent submissions are never
instanced. Draws with explicit `drawOrder` are not instanced, even with an
opaque material. The internal `LiberaFxRenderOrdering` stage sorts visible
submissions before batching by render queue, authored draw order (default 0),
transparent camera depth (far to near), then stable submission-lifetime ID.
Future backends can consume the same keys without changing package formats.
Unity can re-sort these Graphics calls. Direct submission does not guarantee
former `Renderer.sortingOrder` behavior for overlapping layers or global
interleaving with external scene renderers. This is an intentional trade-off
for eliminating per-layer Renderer components.
The adapter exposes cumulative `LiberaFxSpawnableComponent.RenderStatistics`
(active direct submissions, direct draw/instanced calls and dynamic vertex uploads);
counts are observations, not performance claims.

Each `LiberaFxUnityMaterialBinding` can define `parameterMappings` entries with
an exact `authoredName` and `unityPropertyName`, for example `Color` ->
`_Color`. This mapping is local to that material identity; no automatic
underscore prefixing or global name guessing is performed. Every authored
scalar/vector/texture parameter used by a render node must have one mapping.
Duplicate authored names or Unity targets, missing mappings, nonexistent
shader properties, and scalar/vector/texture type mismatches fail preflight
before native OnStart. The package's authored parameter name remains unchanged;
the mapping only selects the Unity property used by MaterialPropertyBlock.

GPU nodes require the package's executable `GpuPrograms` payload and an
explicit GPU program binding by node GUID: imported Unity ComputeShader,
matching Unity metadata TextAsset, billboard Material, every declared texture
resource, and spawn rate. Export/import the UnityCompute shader and metadata
together; runtime shader compilation and filesystem-path loading are not used.
The Unity payload's program/content/source hashes are checked against the
imported binding. GPU buffers and simulation age are per root/Spawnable scope. Root seed comes
from the binding asset; a Spawnable scope starts from its native instance seed.
Each GPU node GUID is mixed into that scope seed. GPU resources
end with their CPU owner on Stop/natural finalization. Root GPU together with
`AutoDestroyWhenIdle` is rejected because this adapter cannot truthfully drain
GPU work after CPU idle; use `AutoDestroyWhenIdle=false`, then call
`RequestNaturalEnd` or `Stop`. Legacy packages with authored GPU snapshots but
without executable GPU programs must be re-exported. CPU-only legacy packages
remain supported.

The host event callbacks run synchronously on Unity's main thread. Use their
container GUID bytes and pool-scoped instance IDs to associate engine objects.
`NativeSpawnableHost.ReadChildValue` reads template outputs while the instance
is active. The component interprets render/GPU payloads and instantiates
root/per-instance scopes from an explicit Unity binding asset. The importer
preserves LFXP bytes; host creation performs native package validation and
reports errors rather than falling back.

Playback uses Unity's scaled `Time.deltaTime`; `playRate` scales effect age,
while the graph Delta Time input receives Unity's frame delta unchanged.
Setting playRate to zero or pausing Unity time holds lifecycle and GPU scope
time. Explicit Stop retires scopes without natural Destroy. Host callbacks and
render updates run on Unity's main thread. Emitted game-I/O events include
their port name. `SetGameProperty`, `FireGameSignal`, `DispatchSignal`,
`SetOwnerMatrix` and `RequestNaturalEnd` are available on the component.

`GetTemplateCount`, `GetTemplateId` and `GetTemplatePayload` are available on
the native host wrapper and component. Use the big-endian container ID from
the template list or a Spawn event to copy RenderConfiguration or GpuContainers.
The byte arrays are owned by the caller, not pointers into the host. Cache
them during setup, not every frame. Payload bytes have no added terminator;
GPU container snapshots remain JSON, not executable GPU programs.
`GetRootPayload` copies the corresponding root-level payload, using the same
SpawnableTemplatePayloadKind selector. Ordinary Groups belong to the root;
Spawnable contents remain in template payloads. LFXP v2/package v10 preserves
these root fields. Legacy v1/package v9 still loads, but root payloads are empty;
re-export the source graph to recover root rendering metadata.
The C ABI supports a null/zero-capacity size query; a short buffer returns
InsufficientWork with the required size and does not partially copy data.
Metadata access does not advance time or fire OnStart. It remains valid until
the native host is disposed; the component releases its host on Stop and then
returns NotReady. Use a matching rebuilt native DLL for these additive APIs.
The component also uses these payloads to create and update render scopes.
The root equivalent is `libra_spawnable_host_copy_root_payload`; both copy APIs
return caller-owned bytes and retain metadata after native host Stop.

Payload kinds include `RenderConfiguration`, `GpuContainers` (authored
snapshots) and `GpuPrograms` (executable package manifest). Root metadata covers
the root graph; Spawnable metadata is per template. The component copies and
preflights these payloads during Play setup. Use a native plugin exposing the
matching package and game-I/O C ABI.

Before the object-free renderer migration, a focused Unity 7000.0.0a16 project
passed CPU root/per-instance renderer updates, named echo output, captured/live
values across two instances, scope cleanup, and authored `Color` -> Unity
`_Color` property mapping with preflight rejection cases. GPU Spawnable and
fractional-spawning checks also passed on D3D11/AMD Radeon RX 6700 XT. These
earlier tests are not player/IL2CPP,
console or cross-platform validation. Current direct-draw/Spawnable checks,
commands, fixtures and limits are recorded in `Editor\Tests\VALIDATION.txt`.

Low-level lifetime API
----------------------
NativeInstance.StartLifetime starts a root with an explicit duration or an
infinite lifetime; StartCapturedLifetime instead reads a Life Time node at
initial evaluation. An optional cached NativeSignal selects On Start; pass null
if absent. AdvanceLifetime takes absolute elapsed seconds and returns a
NativeLifetimeSample. Expired means the root reached its deadline, not that
children or delayed work are finished. ReadValues obtains the last evaluation
without evaluating again. FCurves do not extend the lifetime.

The host must track children and pending work, process their events in time
order, and call DrainLifetime as needed after the root expires. Only after that
work is complete should it call DispatchNaturalDestroy (if an On Destroy
signal exists), wait for any work it creates, and call FinishLifetime.
StopLifetime is an explicit interruption and does not fire natural Destroy.
Check every NativeResult, and dispose the instance when no longer needed.
These are low-level calls only; `NativeInstance` does not host Spawnable
packages. `NativeSpawnableHost` is the low-level lifecycle/package bridge.
`LiberaFxSpawnableComponent` additionally owns Unity root and per-instance
render scopes when supplied a complete `LiberaFxUnityBindingAsset`.

Program creation COPIES bytecode and owns v3 builtin binding storage. v1/v2/v3
and supported v4/v5 load through the real Core validator; unknown non-builtin custom nodes fail.
Instances own fixed-capacity work/default/handle vectors allocated only at create.
Instances retain their Program after program handle release. Handles are never
reused. Repeated release, null storage and unknown handles return errors.
Bind once; tokens are local to their instance and value/parameter namespaces.
Calls are globally serialized; evaluate is synchronous on the caller via the
inline scheduler and reports completed evaluation errors. This prioritizes
safety over parallel instance throughput. No engine/Unity calls run in Core.
Output arrays and inputs are borrowed for one call only; no aliases allowed.
On errors do not render output arrays; batch output may be partially written.
All pointers must address valid storage of the declared size. A native ABI
cannot validate arbitrary dangling pointers or detect a fabricated byte count.
Bad bytecode, null pointers, nonfinite data and stale public handles are handled
with result codes; allocation/other C++ exceptions never cross the ABI.
Release instances before unloading the plugin. Managed wrappers are IDisposable;
OnDisable is the normal release path, finalizers are only a fallback.

iOS / IL2CPP
------------
For iOS link Core + LbInterop.cpp statically into the Xcode player (build for iOS,
not a desktop dylib), keep cdecl exports visible, and ensure linker dead-strip
does not remove exported libra_* functions. P/Invoke uses __Internal on iOS
players and liberafx_native elsewhere. Android needs the target ABI's .so and
matching Plugin Inspector selection. These platforms were not built here.
Forward P/Invoke uses pinned blittable arrays, not Marshal.Copy or delegates.
No MonoPInvokeCallback/AOT reverse-callback wrappers, delegate lifetime roots or
worker->Unity callbacks are needed. If adding reverse callbacks later, explicitly
root static delegates for the entire native registration and use the platform's
AOT attributes; never call UnityEngine from a native worker callback.

CPU particle Sprite billboards
------------------------------
Whole-effect CPU packages use LFXP format 4/package 12 with
`cpuParticleVersion: 1` and a `cpuParticles` render-configuration array.
Template CPU systems or nested Spawnables use format 5/package 13 instead.
Unity resolves each `assetPath` through the existing project-local render asset
bindings (or the explicit `builtin:white` token). One reusable dynamic mesh,
owned material and direct draw submission per CPU emitter carry the particles'
individual RGBA and XY size; no particle or renderer GameObjects are created.
The bundled `LiberaFx/CPU Particle` shader must be present in Resources; it
billboards in the rendering camera's view, including when that camera moves
after the host update. No MainCamera tag is required. The adapter requires
32-bit mesh index support and handles Alpha or Additive blending. Transparent
sorting is by emitter, not by particle. `drawScale` multiplies effect-local
position and XY particle size. Native snapshots are read on the main thread.

The managed C ABI wrapper requires a native SDK/plugin that exports
`libra_spawnable_host_cpu_particle_count`, `libra_spawnable_host_cpu_particle_at`,
and `libra_spawnable_host_cpu_particle_pop_event` (80-byte snapshots, 88-byte
events). On the main thread, call `LiberaFxSpawnableComponent.PopCpuParticleEvent`
or the native managed host equivalent until `hasEvent` is false. Kind 1 is
Property and kind 2 is Signal; read `Width` lanes from X/Y/Z/W. Rendering does
not consume events. Drain each frame and before Stop/restart; queue capacity
must accommodate the output from one simulation advance.

CPU Sprite rendering works at the root and in nested Spawnable scopes. Each
dynamic instance owns its particle storage and direct batch. Life Time stops
emission, then waits for particles and descendants before removing rendering.
Use PopScopedCpuParticleEvent(containerId, instanceId, ...) for a child queue;
the original PopCpuParticleEvent continues to read only the root queue.
The native plugin must additionally export the scoped_cpu_particle_count,
scoped_cpu_particle_at and scoped_cpu_particle_pop_event functions under the
libra_spawnable_host_ prefix. Rebuild the plugin; the older released bridge
does not support format 5. LiberaFxHierarchyVerification.Run exercises a
compiler-produced nested fixture, retained pixels, subtree force and restart.

Flexible Plane uses the same direct camera submission route. Its native
geometry generator must be exported by the installed `liberafx_native` plugin;
the isolated public playback geometry/pixel check is
`LiberaFx.Unity.Editor.LiberaFxRenderSubmissionVerification.RunFlexiblePackage`.
