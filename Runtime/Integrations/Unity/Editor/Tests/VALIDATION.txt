Real Unity Editor verification
==============================

LiberaFxEditorVerification.RunBatch is a synchronous executeMethod test for a
DEDICATED project, not a user's normal scene/project. It creates and cleans up
its own temporary Unity objects, uses the bundled v2 native bytecode fixture,
and writes verification-result.txt and three framebuffer PNGs to that project's
root. It invokes the actual MonoBehaviour lifecycle/update methods through
cached delegates in the Editor; it does not enter Play Mode.

Copy LiberaFx Runtime/Editor directories and the matching native plugin into
Assets\LiberaFx and Assets\Plugins\x86_64 of a dedicated project. No third-party
packages are needed. Minimal projects require the built-in
com.unity.modules.jsonserialize module for the adapter's GPU metadata code.
Windows command, using your own dedicated project and log paths:

  "C:\Program Files\Unity\Hub\Editor\6000.2.6f1\Editor\Unity.exe" -batchmode -quit -noUpm -disable-assembly-updater -force-d3d11 -projectPath "<dedicated project>" -executeMethod LiberaFx.Unity.Editor.LiberaFxEditorVerification.RunBatch -logFile "<dedicated project>\unity-editor.log"

Use a bounded process timeout and stop only that process if it hangs. Do not
add -nographics when checking GPU output: a Null graphics device skips shader
compilation, vertex GPU-buffer identity and framebuffer checks explicitly.
Normal completion exits through -quit; a test failure requests exit code 2.

For the focused native lifetime check without framebuffer rendering, use
LiberaFx.Unity.Editor.LiberaFxEditorVerification.RunLifetime instead. It writes
lifetime-verification.txt and covers explicit and captured lifetimes, expiry,
drain, finish and stop. This does not verify a Spawnable package or Play Mode.

For real Spawnable MonoBehaviour scheduling, use a dedicated project and set
LIBERAFX_UNITY_SPAWNABLE_FIXTURE to the compiler-produced Fireworks.lfxp FILE.
Optionally set LIBERAFX_UNITY_SCRIPT_ACTION_FIXTURE to ScriptAction.lfxp,
emitted by GameIoCompilationTests under LIBERAFX_INSTANCE_GAMEIO_FIXTURES,
to also check script dispatch, replies, and playback replacement.
Run -batchmode -nographics -projectPath "<dedicated project>" -executeMethod
LiberaFx.Unity.Editor.LiberaFxSpawnablePlayModeVerification.Run -logFile
"<dedicated project>\spawnable-playmode.log". Do NOT add -quit: this asynchronous
test enters Play Mode, survives the domain reload, and exits the Editor itself.
It temporarily enables domain reload and restores the dedicated project's
previous Enter Play Mode Options setting before exiting.
It imports a temporary LFXP asset, configures an inactive component, and lets
Unity invoke OnEnable/Update/OnDisable/OnDestroy (no reflected lifecycle calls).
It checks template identity and owned root/template render/GPU payload access, child draining,
exact natural Destroy ordering/times/identities, manual Stop, pause/resume,
restart and cleanup. Metadata access after component Stop must return NotReady.
It writes
spawnable-playmode-verification.txt and deletes only its temporary import.
Use a bounded process timeout. This check needs no GPU or Unity Test Framework.

Unity resource identity adapter/runtime delivery verification
=============================================================

LiberaFxResourceIdentityVerification.RunBatch exercises the real Unity Editor
AssetDatabase, the adapter's JSON request entry point, and the runtime
LiberaFxUnityBindingLookup. It creates a temporary Texture2D and Material,
checks project status/initialization, stable GUID/local-file-ID probes, shader
schema and parameter probes, wrong-project/format/type failures, rename
persistence, explicit binding delivery, and runtime resolution of the delivered
texture, material and authored parameter name.

Run only in a dedicated validation project. Set
LIBERAFX_VERIFICATION_PROJECT to that project's exact absolute path. The
verification refuses to run from a different project, refuses to overwrite an
existing Assets/LiberaFx/LiberaFxBindings.asset or
resource-identity-verification.txt, and never chooses a project-clone policy.
If the dedicated project has no identity yet, it explicitly initializes one;
that project identity asset and Library marker remain after the check. The
temporary fixture assets and the newly-created binding asset are deleted.

The project must contain the LIBERA FX Unity Runtime and Editor sources and the
LiberaFx/Atlas Unlit shader. Use a unique Editor log path:

  $env:LIBERAFX_VERIFICATION_PROJECT = (Resolve-Path "<dedicated project>").Path
  & "<Unity Editor>\Unity.exe" -batchmode -quit `
    -projectPath "$env:LIBERAFX_VERIFICATION_PROJECT" `
    -executeMethod LiberaFx.Unity.Editor.LiberaFxResourceIdentityVerification.RunBatch `
    -logFile "<unique local log path>"

The Unity check emits resource-identity-verification.txt under that dedicated
project. It validates the actual runtime lookup with the adapter-generated
opaque identity. The managed ResourceIdentityScopedPackageTests separately
checks compiler output canonicalization against the binding-asset delivery
GUID/local-file-ID key and Unity authored-parameter-name contract. This is not
a player/IL2CPP build or a rendered-pixels test.
