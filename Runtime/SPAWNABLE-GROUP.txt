Runtime Spawnable Group contract

`GeneratorPool` is engine-neutral. One immutable template `Program` is shared;
each runtime instance owns its
own aligned work, defaults, custom state and spawn time. IDs are nonzero and
never reused within a pool. `evaluate` uses elapsed time, not global time.
Without an explicit lifecycle configuration, instances live until manual stop,
reset or pool destruction; no automatic finish condition is inferred. The
Program, its backing bytecode, descriptors and bindings must outlive the pool.

An owner creates a pool with finite instance, memory and queue limits.
The legacy pool queues at most 16 scalar parameter lanes per spawn. The additive
`createWithCaptureLimit` / `libra_generator_pool_create_ex` allow 1..256 lanes
per command, charged to the finite memory budget. The legacy C enqueue remains
limited to 16; `libra_generator_enqueue_spawn_ex` uses the configured bound.
`enqueueSpawn` snapshots lanes without allocation and
can be called concurrently, including from native signal callbacks. The owner
calls `processSpawns` after callback dispatch; a failed command stays queued and
the error is returned. `spawn` is the synchronous owner-thread alternative.
Each captured lane identifies a template node GUID, input slot and component.
The target must be an unconnected default; connected targets are rejected.
Capture is at spawn, not a live parent binding. All pool operations except
enqueue must run on one owner thread.

Spawn and stop events contain the container GUID, pool-scoped instance ID and
start time and deterministic instance seed. Drain the bounded event queue on the engine's owner thread; a full
queue rejects operations rather than losing notifications. `reset` atomically
rejects if there is not enough event space for all stops, otherwise retires all
instances and discards queued spawns. Before destroying a pool, reset and drain
events if the host requires stop notifications. No callback creates engine
objects. The C ABI exposes equivalent POD records and retains the program.

Configured lifecycle (opt-in; old pools and C ABI calls are unchanged)

Configure an empty pool with `GeneratorLifecycle` or the 40-byte,
4-byte-aligned `LibraGeneratorLifecycle` (`onStartNodeId[16]`, `lifeNodeId[16]`,
`flags` at byte 32, `instructionBudget` at byte 36). Flags 1 and 2 enable
OnStart and Life respectively. Life is sampled and captured once by start;
later Live changes never extend or shorten it. The legacy core API accepts a
non-negative scalar duration in seconds; zero expires after OnStart. Authored
package-v2 Life Time requires strictly positive finite seconds. Signal
traversal is limited to 1..10000 instructions. Node IDs are big-endian.

Spawn initializes one independent instance and applies captured values. Drain
its Spawn record, set its initial Live lanes, then call `GeneratorPool::start`
or `libra_generator_start`. Start evaluates at local time zero and dispatches
OnStart once after input setup; repeated calls do not refire it. If signal
dispatch fails, the same error remains latched; stop or reset the instance.
An instance cannot evaluate before start. For later frames, update Live lanes
before evaluate; captured lanes are not automatically refreshed.

When elapsed local time reaches the captured Life value, evaluation samples at
the exact expiry boundary (clamping overshooting frames), freezes the instance
and emits one event kind 3, Destroy. This is a local group output, never a game
callback. Route it only to its immediate parent; game output requires an
explicit graph connection. Frozen values remain readable for that routing, but
the instance cannot evaluate or accept Live updates. After draining and routing
Destroy, call `GeneratorPool::finalize` / `libra_generator_finalize`; this emits
the ordinary stop record and releases the frozen instance. Manual stop, reset,
release and teardown never create Destroy. Stop/reset return Busy for a
naturally expired instance until it is finalized.

If event backpressure prevents Destroy from being queued, start/evaluate returns
QueueRejected. Drain existing records and retry; no evaluation or OnStart is
replayed. Once Destroy is queued, further evaluate/start returns NotReady.
Finalize returns QueueRejected if the stop record cannot fit; drain and retry.
Signal callbacks may enqueue future spawns, but may not reenter evaluation,
start, stop, reset, delivery, or create/destroy engine objects. Cleanup cannot
enqueue spawns. Core callbacks may call `GeneratorPool::enqueueSpawn` directly;
they must not reenter any C ABI function (the C ABI serializes calls). The
existing native spawn-signal bridge enqueues directly. No local Destroy is
implicitly published to named game IO.

Editor package and host bridge (v2)

The Spawnable Group context action creates one editable child graph. Add up to
four typed Spawn Input nodes directly inside it; their GUIDs become parent
parameter-port IDs and template capture targets. A signal enqueues one runtime
instance, never another graph node. Nested Spawnable Groups are rejected.
`SpawnableGroupPackage.Compile` emits the parent LFXB, separate template LFXBs,
capture maps, per-template render configuration and GPU container snapshots.
MCP `libera_graph_compile_spawnable` exposes this as JSON package version 2.
It adds a direct root On Start identity, per-template On Start/Life Time
identities, Group Output (Vector3) mappings and explicit Destroy routes.
Exactly one direct Life Time per template is supported; none means infinity.
Multiple Life Times and nested Spawnables are rejected. Busy/FCurve are never
implicit lifetime participants. The existing `then` pin remains immediate for
old projects; `destroy` is a separate natural-expiry-only local event pin.
Local outputs can currently route only from the expiring instance directly to
the capture inputs of the sibling Spawnable selected by that Destroy route.
Unsupported cross-instance or nested boundary routing fails compilation.
`NativeSpawnableSession` is a .NET owner-thread host adapter using the C ABI:
it drives native start/evaluate, reads frozen outputs, captures the target
defaults, starts the sibling at the expiry timestamp, then finalizes the source.
Recreate the session for deterministic reset. Its CPU support is not UE preview
support, and GPU containers fail explicitly.
Template GUIDs remain unchanged between runtime instances. GPU containers are
host payloads and are not flattened into CPU numeric instructions.

For each template, load its LFXB once, create a bounded pool using its container
GUID, then populate `LibraSpawnableBinding` from the package's signalTypeId,
input widths, Color flags and templateNodeIds. Load the parent with
`libra_program_create_spawnable`; evaluate its instance and dispatch its signal
entry with `libra_dispatch_signal`. Evaluate the parent at the signal's time
before dispatch, since capture reads the most recent evaluated parent values;
multiple signals in that frame may reuse that evaluation. The callback only queues captures. Call
`libra_generator_process_spawns` and drain lifecycle events outside the callback.
The loader registers the package's signal passthrough type
989fa5b5-485f-4e75-8542-9c5500000001. A template containing Signal nodes can
also be loaded with `libra_program_create_spawnable` and zero bindings. These
are host ABI records and handles, not wire overlays or engine pointers. A pool
cannot be released while a loaded parent program retains it; release parent
instances and programs first.
If a package has no Spawnable Groups and its parent bytecode is v1 or v2,
load it with `libra_program_create` instead.

UE/Unity adapters must consume the lifecycle and render/GPU payloads separately;
this code does not instantiate engine objects. Diagnostics should identify the
container GUID, template node GUID and pool-scoped instance ID together.

Work in progress: explicit named game IO and live updates

`NamedIo` is an owner-thread C++ primitive for explicitly game-facing ports,
not group-local boundaries. It copies bounded descriptors, validates unique
names and supported scalar/vector widths, evaluates before OnStart, and queues
initial/change-only property records and explicit output signals. The caller
drains records and invokes game delegates outside evaluation. Records carry a
caller-supplied container/instance identity. A group output, including Destroy,
must never be published to game IO without an explicit graph connection.
`GeneratorPool::setLive` / `libra_generator_set_live` apply host-selected lanes
to one instance before evaluation; CaptureAtSpawn values remain unchanged unless
the host incorrectly includes them. The package/editor do not yet expose Live
policy or drive these primitives automatically. Named IO node compilation, C ABI
game IO, general group routing and automatic engine OnStart integration are not
implemented by these primitives and must not be advertised as complete.
Editor-native preview (Root execution ownership):
CompiledPreviewSender now owns a NativeSpawnableSession through
EditorNativePreviewSession for lifecycle graphs. Configure the matching native
library with an absolute LIBERAFX_PREVIEW_NATIVE_LIBRARY, or place the DLL beside
the editor. Missing native/ABI produces CompileError, never simulated lifetime.
Root drives actual bounded C++ pools, captures frozen Destroy outputs before
finalize, and sends evaluated per-instance render defaults. Renderer UUID hashes
include container, pool-scoped instance ID and template draw node ID.
UE still receives one inert Scalar LFXB transport shell and render_config;
its wire Play/Loop flags are zero to prevent engine-owned free-running.
Scene metadata explicitly says executionOwner=editor-native and
standaloneEngineLifecycle=false. UE does not load the v2 package or run its pools.
Pause/resume/equal-time resync retain state without evaluation. Backward seek,
Stop-to-zero and Loop recreate pools and replay fixed 60Hz steps; forward dropped
frames execute missing steps. Requested time is sampled down to the 60Hz grid.
Replay is capped at 120 seconds, scene renderers at 128 and bytes at 1MiB.
Graph/document changes and disconnect dispose the owner session. Native core
callbacks still perform no engine SDK operations. Broader authored lifetime
policies beyond one captured positive scalar node remain outside this contract.
Existing package-v1 spawn signal descriptors still carry at most four typed
inputs (16 lanes), and their legacy `then` branch is selected immediately on
spawn dispatch. Do not map that branch to lifetime Destroy: the compiler and
host adapter must explicitly replace it with event-kind-3 local routing and
extend the package/binding contract before exposing larger authoring ports.
