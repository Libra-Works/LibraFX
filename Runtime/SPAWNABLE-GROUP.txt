Runtime Spawnable Group contract

`GeneratorPool` is engine-neutral. One immutable template `Program` is shared;
each runtime instance owns its
own aligned work, defaults, custom state and spawn time. IDs are nonzero and
never reused within a pool. `evaluate` uses elapsed time, not global time.
Without an explicit lifecycle configuration, instances live until manual stop,
reset or pool destruction; no automatic finish condition is inferred. The
Program, its backing bytecode, descriptors and bindings must outlive the pool.

An owner creates a pool with finite instance, memory and queue limits.
The legacy pool queues at most 16 scalar parameter lanes per spawn. The additive
`createWithCaptureLimit` / `libra_generator_pool_create_ex` allow 1..256 lanes
per command, charged to the finite memory budget. The legacy C enqueue remains
limited to 16; `libra_generator_enqueue_spawn_ex` uses the configured bound.
`enqueueSpawn` snapshots lanes without allocation and
can be called concurrently, including from native signal callbacks. The owner
calls `processSpawns` after callback dispatch; a failed command stays queued and
the error is returned. `spawn` is the synchronous owner-thread alternative.
Each captured lane identifies a template node GUID, input slot and component.
The target must be an unconnected default; connected targets are rejected.
Capture is at spawn, not a live parent binding. All pool operations except
enqueue must run on one owner thread.

Spawn and stop events contain the container GUID, pool-scoped instance ID and
start time and deterministic instance seed. Drain the bounded event queue on the engine's owner thread; a full
queue rejects operations rather than losing notifications. `reset` atomically
rejects if there is not enough event space for all stops, otherwise retires all
instances and discards queued spawns. Before destroying a pool, reset and drain
events if the host requires stop notifications. No callback creates engine
objects. The C ABI exposes equivalent POD records and retains the program.

Configured lifecycle (opt-in; old pools and C ABI calls are unchanged)

Configure an empty pool with `GeneratorLifecycle` or the 40-byte,
4-byte-aligned `LibraGeneratorLifecycle` (`onStartNodeId[16]`, `lifeNodeId[16]`,
`flags` at byte 32, `instructionBudget` at byte 36). Flags 1 and 2 enable
OnStart and Life respectively. Life is sampled and captured once by start;
later Live changes never extend or shorten it. The legacy core API accepts a
non-negative scalar duration in seconds; zero expires after OnStart. Authored
package-v2 Life Time also accepts non-negative finite seconds. Signal
traversal is limited to 1..10000 instructions. Node IDs are big-endian.

Spawn initializes one independent instance and applies captured values. Drain
its Spawn record, set its initial Live lanes, then call `GeneratorPool::start`
or `libra_generator_start`. Start evaluates at local time zero and dispatches
OnStart once after input setup; repeated calls do not refire it. If signal
dispatch fails, the same error remains latched; stop or reset the instance.
An instance cannot evaluate before start. For later frames, update Live lanes
before evaluate; captured lanes are not automatically refreshed.
For package-v7 inputs sourced from parent nodes, drain the Spawn record, apply
the mapped CaptureAtSpawn lanes with `GeneratorPool::setCaptured` /
`libra_generator_set_captured`, then apply Live lanes and start. This API
rejects updates after start and does not change template defaults.

`Owner Destroy` is a natural owner end request, not destruction of the child.
The host processes children reaching their own expiry at that timestamp first,
then sends the request once to every surviving child, including children
created later during draining. The child may ignore it and continue until its
own natural expiry; the parent must not force-stop it. After evaluating the
child at the request time, call `GeneratorPool::ownerDestroy` or
`libra_generator_owner_destroy` with the template's ownerDestroyNodeId.
Duplicate calls do not dispatch again, and a dispatch failure is latched so
partial signal execution cannot be replayed. Explicit stop/reset is separate.
The editor-native host sends this request when natural root shutdown begins;
engine hosts must implement it explicitly.

When elapsed local time reaches the captured Life value, evaluation samples at
the exact expiry boundary (clamping overshooting frames), freezes the instance
and emits one event kind 3, Destroy. This is a local group output, never a game
callback. Route it only to its immediate parent; game output requires an
explicit graph connection. Frozen values remain readable for that routing, but
the instance cannot evaluate or accept Live updates. After draining and routing
Destroy, call `GeneratorPool::finalize` / `libra_generator_finalize`; this emits
the ordinary stop record and releases the frozen instance. Manual stop, reset,
release and teardown never create Destroy. Stop/reset return Busy for a
naturally expired instance until it is finalized.

`GeneratorPool::lifetime` / `libra_generator_lifetime` report the last
successfully evaluated local age, remaining duration, normalized age and
expiry state, including the frozen expiry boundary. Before the first successful
start/evaluation they return NotReady; after finalization or stop the handle is
invalid. A zero-duration lifetime reports normalized age 1 at expiry. Infinite
lifetime reports infinite remaining and normalized age 0. Failed updates leave
the previous sample intact. Instance Remaining and Instance Normalized Age
are available as graph nodes;
infinite remaining cannot be represented and is rejected at compile time.
`liberafx::SpawnableHost` loads this versioned package and owns the shared
effect/Spawnable lifecycle, routing, game I/O and bounded host events without
engine dependencies. Unity and Unreal components are not wired to this host yet;
they must consume its lifecycle and render/GPU payloads separately.
The `Instance Age` graph node reads local elapsed seconds for the effect or
Spawnable, using the same sample time as native evaluation.
`Effect Age` reads seconds since the root effect began, even inside a
Spawnable; an ordinary Group inherits the enclosing instance's clock.
`Delta Time` is the game host's frame delta, shared by instances and unchanged
when the lifecycle host splits a frame at expiry or scheduled events. The host
must call Instance::setTimeContext / libra_instance_set_time_context before
each root evaluation, and GeneratorPool::setTimeContext /
libra_generator_set_time_context before each child start/evaluation. Missing
context returns NotReady rather than substituting local or substep time.
Both values must be finite and nonnegative. NativeSpawnableSession.Advance
accepts an explicit frame delta; its one-argument overload derives delta from
elapsed time for the fixed-step editor preview only. At replay start the
preview uses zero and later uses its fixed 1/60-second simulation steps.
The C++ Instance and CustomNodeInvocation layouts have changed: rebuild hosts
and native node modules against the matching runtime headers and library.

If event backpressure prevents Destroy from being queued, start/evaluate returns
QueueRejected. Drain existing records and retry; no evaluation or OnStart is
replayed. Once Destroy is queued, further evaluate/start returns NotReady.
Finalize returns QueueRejected if the stop record cannot fit; drain and retry.
Signal callbacks may enqueue future spawns, but may not reenter evaluation,
start, stop, reset, delivery, or create/destroy engine objects. Cleanup cannot
enqueue spawns. Core callbacks may call `GeneratorPool::enqueueSpawn` directly;
they must not reenter any C ABI function (the C ABI serializes calls). The
existing native spawn-signal bridge enqueues directly. No local Destroy is
implicitly published to named game IO.

Editor package and host bridge (v2-v8)

The Spawnable Group context action creates one editable child graph. Add typed
Spawn Input nodes directly inside it; their GUIDs become parent parameter-port
IDs and template capture targets. Existing package versions carry up to four
inputs (16 lanes) through the Spawnable custom-node binding. Version 7 stores
source mappings in the package for larger templates, up to 256 total scalar
lanes. The host reads parent values at the spawn timestamp and applies
CaptureAtSpawn values before OnStart; Live values are updated before start and
each child evaluation. A signal enqueues one runtime instance, never another
graph node. Nested Spawnable Groups are rejected.
The editor distinguishes expandable lifecycle owners, Life Time and
non-container Delay nodes with role labels and theme-colored badges. Visible
summaries show configured seconds, including published instance overrides;
connected seconds inputs are marked input-dependent. These are durations,
not predicted final destruction times. Double-click a non-interactive part
of a group to enter it. With no child selected, the inspector shows the
immediate containing Spawnable's published values and curves. Editing/reset
changes that instance's overrides through undo/redo, not child template
defaults; it does not navigate away or select an out-of-scope node.
`SpawnableGroupPackage.Compile` emits the parent LFXB, separate template LFXBs,
capture maps, per-template render configuration and GPU container snapshots.
MCP `libera_graph_compile_spawnable` exposes JSON package format version 9.
Versions 2 through 8 introduced lifecycle routing, root and Spawnable Delay,
per-pin CaptureAtSpawn/Live bindings, extended inputs, and local Signal I/O.
Version 9 adds the root `AutoDestroyWhenIdle` policy. Older hosts must reject
unknown versions rather than silently ignoring these semantics.
It adds direct root On Start/On Destroy identities, per-template On Start,
Life Time and Owner Destroy identities, typed Group Output mappings and
explicit Destroy routes.
The effect root has no Life Time; a root Life Time is an authoring diagnostic
and compilation error. Exactly one direct Life Time per template is supported;
none means infinity.
Multiple Life Times and nested Spawnables are rejected. Busy/FCurve are never
implicit lifetime participants. The existing `then` pin remains immediate for
old projects; `destroy` is a separate natural-expiry-only local event pin.
Float, Vector2, Vector3, Vector4 and Color Group Outputs can route only from the
expiring instance to the capture inputs of a sibling Spawnable selected by that
Destroy route. A single Delay can
be inserted between root sibling Destroy and Spawn. Its finite nonnegative
seconds are sampled at Destroy; zero fires at the same timestamp. The expired
child's outputs are captured then, while ordinary parent inputs are captured at
the delayed Spawn time. The pending event keeps the parent alive.
Root Signal paths can also use Delay, including chains and fan-out. These
continuations use the owning effect's elapsed time, not a game-global timer;
changing the effect's playback speed changes when the due time is reached.
The host must evaluate at each due local time, dispatch the continuation and
retain the root until its deferred signals and spawned children drain.
Spawn Input (Signal) ports broadcast to every started, non-expiring instance in
that template. Spawn remains a creation command: it creates a new instance and
is never broadcast. Spawn Output (Signal) emits an event carrying the originating
instance and effect time; the host routes each event separately through the
parent connections. Natural Destroy remains its own per-instance lifecycle
event and is not a general Signal output.

Before spawning, configure each template pool's local signal output node IDs
with `GeneratorPool::setSignalOutputs` / `libra_generator_set_signal_outputs`.
The host delivers an input with `GeneratorPool::dispatchSignal` /
`libra_generator_dispatch_signal`, which visits all currently active instances.
Drain `GeneratorSignalEvent` / `LibraGeneratorSignalEvent` records separately
from Spawn/Stop/Destroy records. Parent output routes are dispatched at the
event time using `libra_effect_dispatch_signal`; it accepts only the root
lifecycle's last evaluated time. After natural end is requested, hosts reject
new external game signals but continue dispatching internal child routes while
the root drains.
Explicit Stop cancels pending signals without sending Destroy.
Inside a Spawnable, Delay uses that instance's local clock and retains the
instance after Life Time while continuations remain. Its Instance Age keeps
advancing; remaining lifetime stays zero. Natural Destroy is emitted only
after the last continuation finishes, using that actual completion time and
its final evaluated values. The root waits for the child and subsequent
Destroy-routed sibling work. Ordinary Graph Groups inherit their enclosing
effect/Spawnable clock, including Delay routed through group signal boundaries.
Nested Spawnable ownership and lifecycle routing remain unsupported.
One delayed Destroy can fan out to multiple sibling Spawn targets; each branch
retains the parent until its scheduled spawn and resulting child finish.
The root's natural end begins after startup/queued work drains when
`AutoDestroyWhenIdle` is enabled and at least one Spawnable template exists.
With no Spawnables, or when the setting is disabled, the root remains available
for game signals until the host explicitly requests natural end. The root On
Destroy signal runs once after that request and existing children and scheduled
events have drained. If that signal starts new children,
the root waits for them too; it does not dispatch On Destroy again. Explicit
Stop and reset do not dispatch it. This is a local graph entry and does not
implicitly create a game-facing Output Signal.
`NativeSpawnableSession` is a .NET owner-thread host adapter using the C ABI:
it drives native start/evaluate, reads frozen outputs and finalizes the source,
then starts the sibling immediately or at its scheduled time.
Recreate the session for deterministic reset. Its CPU support is not UE preview
support, and GPU containers fail explicitly.
Template GUIDs remain unchanged between runtime instances. GPU containers are
host payloads and are not flattened into CPU numeric instructions.

For each template, load its LFXB once, create a bounded pool using its container
GUID, then populate `LibraSpawnableBinding` from the package's signalTypeId,
input widths, Color flags and templateNodeIds. Load the parent with
`libra_program_create_spawnable`; evaluate its instance and dispatch its signal
entry with `libra_dispatch_signal`. Evaluate the parent at the signal's time
before dispatch, since capture reads the most recent evaluated parent values;
multiple signals in that frame may reuse that evaluation. The callback only queues captures. Call
`libra_generator_process_spawns` and drain lifecycle events outside the callback.
The loader registers the package's signal passthrough type
989fa5b5-485f-4e75-8542-9c5500000001. A template containing Signal nodes can
also be loaded with `libra_program_create_spawnable` and zero bindings. These
are host ABI records and handles, not wire overlays or engine pointers. A pool
cannot be released while a loaded parent program retains it; release parent
instances and programs first.
If a package has no Spawnable Groups and its parent bytecode is v1 or v2,
load it with `libra_program_create` instead.

The portable host does not instantiate engine objects. UE/Unity adapters must
consume lifecycle and render/GPU payloads separately. Diagnostics should
identify the container GUID, template node GUID and pool-scoped instance ID
together.

Work in progress: explicit named game IO and live updates

`NamedIo` is an owner-thread C++ primitive for explicitly game-facing ports,
not group-local boundaries. It copies bounded descriptors, validates unique
names and supported scalar/vector widths, evaluates before OnStart, and queues
initial/change-only property records and explicit output signals. The caller
drains records and invokes game delegates outside evaluation. Records carry a
caller-supplied container/instance identity. A group output, including Destroy,
must never be published to game IO without an explicit graph connection.
`GeneratorPool::setLive` / `libra_generator_set_live` apply host-selected lanes
to one instance before evaluation; CaptureAtSpawn values remain unchanged unless
the host incorrectly includes them. The package/editor do not yet expose Live
policy or drive these primitives automatically. Named IO node compilation, C ABI
game IO, general group routing and automatic engine OnStart integration are not
implemented by these primitives and must not be advertised as complete.
Editor-native preview (Root execution ownership):
CompiledPreviewSender now owns a NativeSpawnableSession through
EditorNativePreviewSession for lifecycle graphs. Configure the matching native
library with an absolute LIBERAFX_PREVIEW_NATIVE_LIBRARY, or place the DLL beside
the editor. Missing native/ABI produces CompileError, never simulated lifetime.
Root drives actual bounded C++ pools, captures frozen Destroy outputs before
finalize, and sends evaluated per-instance render defaults. Renderer UUID hashes
include container, pool-scoped instance ID and template draw node ID.
UE still receives one inert Scalar LFXB transport shell and render_config;
its wire Play/Loop flags are zero to prevent engine-owned free-running.
Scene metadata explicitly says executionOwner=editor-native and
standaloneEngineLifecycle=false. UE does not load the v2 package or run its pools.
Pause/resume/equal-time resync retain state without evaluation. Backward seek,
Stop-to-zero and Loop recreate pools and replay fixed 60Hz steps; forward dropped
frames execute missing steps. Requested time is sampled down to the 60Hz grid.
Replay is capped at 120 seconds, scene renderers at 128 and bytes at 1MiB.
Graph/document changes and disconnect dispose the owner session. Native core
callbacks still perform no engine SDK operations. Broader authored lifetime
policies beyond one captured nonnegative scalar node remain outside this contract.
Existing package-v1 spawn signal descriptors still carry at most four typed
inputs (16 lanes), and their legacy `then` branch is selected immediately on
spawn dispatch. Do not map that branch to lifetime Destroy: the compiler and
host adapter must explicitly replace it with event-kind-3 local routing and
extend the package/binding contract before exposing larger authoring ports.

EffectLifecycle is a portable owner-thread primitive for an already-initialized
effect instance. Its caller supplies scaled elapsed seconds and owns the instance
and memory. It evaluates at zero before an optional OnStart signal and clamps
the final evaluation to finite expiry. Equal elapsed times do not reevaluate.
Stop does not report expiry; failed evaluation or signal dispatch is not retried.
It reports the deadline without stopping children. Once the host has drained
owned work, `destroy` / `libra_effect_destroy` dispatches a supplied root signal
at most once; `finish` is separate and the host must wait for any new children.
Its caller-owned lifecycle also contains a bounded 128-entry continuation
queue. `schedule`, `nextScheduled` and `takeScheduled` (and the corresponding
`libra_effect_*` C ABI calls) preserve FIFO order for equal timestamps. The
host must advance/drain to each due time before taking and executing the event;
skipping a pending timestamp and finishing with pending events are rejected.
Taking consumes the event before execution, and explicit Stop cancels pending
events. Instance's separate caller-owned deferred-signal storage supports general
root Delay continuations. EffectLifecycle owns this bounded storage, reports
the next due time and consumes each continuation before dispatch. The owner
must check both queues, updating at the earlier timestamp. At equal times,
NativeSpawnableSession delivers scheduled Destroy routes before deferred
signals; each queue preserves FIFO order.
The C++ Instance, EffectLifecycle and CustomNodeInvocation layouts changed;
rebuild native hosts and node plugins against the matching headers. C ABI hosts
must check for the deferred-signal exports before accepting version 4 packages.
Version 5 additionally requires generator next/dispatch-deferred-signal and
elapsed exports. Set LIBRA_LIFECYCLE_DEFERRED_SIGNALS when configuring its pools.
Each pool slot owns bounded storage for 128 continuations, included in its
memory budget. Query due times in effect-clock seconds, evaluate each instance
at that time, then dispatch its continuation. Query elapsed before retiring
a naturally completed instance; Start + Life is not the completion time when
work drains past the deadline. The lifetime sample itself remains clamped.

Spawn input binding mode defaults to CaptureAtSpawn in older saved graphs.
The input node's Binding mode selector changes only that pin. Live pins retain
their initial capture for startup, then the host applies their LiveInputs
source mappings through libra_generator_set_live before OnStart and every
evaluation, after evaluating the enclosing parent. All lanes are applied as
one validated batch. Read Break sources using SourceComponent, not lane zero;
ordinary group outputs map to their compiled boundary-node identities.
Life Time and a dispatched Delay capture their duration once, even when driven
by a Live pin. Live never keeps extending an existing lifetime or timer.
Live cannot read a naturally completed sibling's final output: choose
CaptureAtSpawn for that Destroy-routed input. The existing four-numeric-pin
bytecode limit remains; arbitrary Signal/Matrix pins and nested ownership
are separate unfinished authoring/compiler/runtime work.
The opt-in libra_effect_start/advance/stop C ABI exposes this primitive for a
fresh instance, optionally with game IO configured before start. Managed game
signals use the last evaluated age; raw evaluation and independent game IO
start/update are disabled. Failed evaluation, publication or OnStart is
terminal rather than replaying partially executed nodes. The editor-native
host uses an infinite root and requests natural end according to
`AutoDestroyWhenIdle` or an explicit host `End` call. Unity exposes low-level
lifetime calls but does not yet host package lifecycle; Unreal does not yet use
this lifecycle API.
libra_effect_start_captured obtains a finite scalar duration from the initial
evaluation, before publishing game properties or invoking OnStart. Later input
changes do not change the captured duration; invalid values fail before OnStart.

Portable engine asset container (LFXP v1)
-----------------------------------------
JSON package v9 remains the compiler/editor interchange format. Engine assets
use a separate LFXP container so LFXB programs and render configurations are
stored as raw bytes instead of base64. The fixed 24-byte header is:

- bytes 0..3: ASCII `LFXP`
- bytes 4..5: container version (little-endian u16, currently 1)
- bytes 6..7: header size (little-endian u16, 24)
- bytes 8..15: total container length (little-endian u64)
- bytes 16..19: Spawnable package version (little-endian u32, currently 9)
- bytes 20..23: reserved, zero

The payload is sequential and little-endian. It contains root policy flags,
nullable root signal IDs, Game I/O descriptors, parent bytecode, templates,
Destroy routes and Signal routes. Every list/blob/string is preceded by a
little-endian signed 32-bit count/byte length; strings are strict UTF-8. GUIDs
are the 16 RFC 4122/network-order bytes used by LFXB. Template data includes
bytecode, render configuration, input/output mappings, lifecycle IDs,
CaptureAtSpawn/Live mappings and Signal boundary mappings. GPU node snapshots
are retained in a length-prefixed UTF-8 JSON blob; GPU execution remains an
engine responsibility. Optional lists and GUIDs have explicit presence flags.
Readers reject unknown versions, invalid counts/flags, truncated payloads and
trailing bytes. The .NET writer and portable C++ reader reject unknown
container/package versions and preserve the decoded output on failure. Engine
asset loaders and the shared lifecycle host remain required before LFXP is a
runtime-ready asset format.

Payload field order is: three u8 root flags (`AutoDestroyWhenIdle`,
`HasDeferredSignals`, `HasChildDeferredSignals`); nullable OnStart and OnDestroy
GUIDs; Game I/O count and records (GUID, UTF-8 name, kind u8, width i32,
isColor u8, runtime-node count i32 where -1 means null); parent bytecode blob;
template count and records; Destroy route count and records; Signal route count
and records. Each template record is container/type GUIDs, bytecode, render
configuration, GPU JSON blob, input count and records, then presence-flagged
Outputs, LiveInputs, CapturedInputs, SignalInputs and SignalOutputs lists, then
a lifecycle presence flag and its three nullable GUIDs. Each Destroy route is
source/target GUIDs, nullable Delay GUID and captures. Each capture is target
GUID, width i32, nullable source-container GUID, source-node GUID and source
component i32. Each Signal route is source-container/source-node/target-node
GUIDs. Inputs are port-ID string, template-node GUID, port-type string, width
i32, isColor u8 and isLive u8; Outputs omit width/flags; Signal ports are
port-ID string, template-node GUID and proxy-node GUID. Optional lists encode
presence u8 then count/records when present. Counts are 0..100000, blobs are at
most 256 MiB and the whole container is at most 512 MiB. Booleans and presence
flags are exactly 0 or 1.
